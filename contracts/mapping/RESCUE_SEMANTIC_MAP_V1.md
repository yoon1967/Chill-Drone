# 인명 구조 의미 지도 1.0

생산자: `modules/mapping/data/stream_mapping.py`, `rescue_mapping.py`.
소비자: `apps/console/`, 점군 전달기, 저장·재생·ZIP 불러오기.

기존 결과와 `pose-depth-history/1.0`에 선택 필드를 추가한다. 기존 필드·좌표 변환은 유지한다.
사람은 정적 점군 통합과 분리해 표시한다. 기본 표시 색은 `#ff3030`이다.
새 작업은 위치 정렬과 복셀별 대표 점 통합만 수행한다. 메시·삼각형·법선을 생성하지 않는다.

## 입력 옵션

| 필드 | 값·기본값 |
| --- | --- |
| `semantic_mapping` | boolean. UI는 true, 이전 API 클라이언트는 생략 시 false |
| `depth_resolution` | 256 / 384 / 518. 의미 지도 기본 384, 기존 경로 256 |
| `person_color` | `#rrggbb`. 기본 `#ff3030` |
| `person_outline` | boolean. 기본 true |
| `live_policy` | sequential / continuous. 기존 API 기본 sequential, 새 실시간 UI continuous |
| `point_budget` | 정수 1,000~32,000. 기본 32,000. UI는 4,000 / 8,000 / 10,000 / 16,000 / 32,000 |
| `sample_fps` | 실시간·빠른 복원에 선택할 목표 프레임/초. 유한한 숫자 0.1~15, UI·실시간 기본 5. 카메라 촬영/녹화·화면 FPS와 별개이며 처리 능력에 따라 실제 반영량은 낮을 수 있음 |

색상·외곽선은 브라우저 설정에 보존하고 표시 중 즉시 변경할 수 있다. 작업 생성 당시 값도
기록하므로 다른 브라우저에서 파일을 열 때 그 값을 사용한다. 의미 지도·해상도·점 개수 변경은 다음 작업부터 적용한다.

## 공간 통합과 누적 비용 제한

고정된 원점의 복셀 안에서 위치·RGB는 신뢰도 가중 평균, 공간 클래스는 가중 투표로 통합한다.
사람 경계는 확장하여 정적 점군에서 제외한다. 같은 영역을 반복 관측해도 점이 계속 추가되지 않는다.
점이 `point_budget`을 넘으면 **전체** 복셀 간격을 고정 증가 폭의 정수 배만큼 넓힌다.
구간의 첫 유효 정적 관측에서 바로 이웃한 점의 3D 거리 중앙값을 구한다.
이 값을 관측 점 수의 10배가 들어오는 경우의 목표 간격으로 환산하고, 그 1/4을 증가 폭으로 삼는다.
증가 폭은 최초 복셀 간격의 1/4~1/2로 제한한다. 유효한 이웃 쌍이 8개 미만이면 하한을 사용한다.
이 값은 지도 구간마다 한 번 정한다. 다음 관측에서 점 수를 한도에 맞출 간격을 찾은 후 그 격자에서 가중 통합을 한 번 실행한다.
좌표는 임의 단위다. 음수 좌표도 같은 원점의 격자 규칙을 따르고, 오래된 셀을 시간순으로 삭제하지 않는다.
지도 범위가 커지면 이전·현재 구간 모두 해상도가 낮아질 수 있다. 가려진 면은 생성하지 않는다.

프레임별 영속 통합 상태는 지도 구간당 한도 이내이며 일시 계산은 한도와 현재 깊이 영상 크기에
비례한다. `render_window_s`는 새 경로에서 null이다. 실시간·최종 결과 모두 같은 공간 예산을 쓴다.
추적이 끊겨 생긴 서로 다른 지도 구간은 별개로 보존한다. 전체 기록 파일과 카메라 경로는 촬영
시간에 따라 증가한다. 이 제한은 점군 메모리·전송·렌더링을 대상으로 한다.

## 프레임 결합

인식에는 깊이와 동일하게 리사이즈·왜곡 보정한 RGB를 사용한다. 결과의 `frame_id`,
`timestamp_s`, 마스크 크기가 처리 프레임과 정확히 일치해야 한다. 불일치하면 실패한다.
이수진 팀원의 YOLO·SegFormer 모델을 재사용하며, 지도용 구조화 추론에서는 공간 마스크도
항상 현재 프레임에서 계산한다. 영상 합성용의 이전 마스크를 3D에 재사용하지 않는다.

위치 추적은 기존 ORB-SLAM3 경로다. 사람 마스크는 깊이 배율을 정렬하는 정적 앵커에서도 제외한다.
카메라 위치가 없거나 유효한 앵커가 8개 미만이면 그 프레임을 임의의 3D 위치에 표시하지 않는다.

## 미리보기의 `rescue`

- `schema_version`: `rescue-semantic-map/1.0`.
- `map_id`: 원래 단안 지도 구간. 서로 다른 지도 구간의 사람·표면은 합치지 않는다.
- `classes`: unknown, person, wall, floor, ceiling, table, chair, door, windowpane 순서.
- `render_mode`: 새 결과는 `points`. 이때 상위 `points`가 실제 표시 점군이다.
- `point_revision`: 해당 지도 점군이 갱신될 때 증가한다.
- `point_labels`: 상위 `points`와 같은 순서·길이의 클래스 인덱스. 최종 scene은 점 ID 순서.
- `point_fusion`: `point_budget`, `static_points`, `voxel_size`, `base_voxel_size`, `spacing_increment`,
  `spacing_policy=fixed_increment`, `coarsenings` (최초 간격에 더한 증가 폭의 단위 수),
  `observations`, `coverage_bounds`, `policy=spatial_voxel_merge_no_age_eviction`.
  `coverage_bounds`는 지금까지 통합한 관측 범위이며 실제 점 중심의 최소·최대와 다를 수 있다.
- `people`: 아래 사람 발견 위치 배열. 최대 32곳.
- `person_color`, `person_outline`: 기록 당시 기본 표시 설정.
- `chunk`: 이전 소비자 호환을 위한 0. 새 결과는 시간에 따라 표면 조각을 초기화하지 않는다.
- `fusion_ms`, `inference_ms`: 프레임 처리 계측. 네트워크·화면을 포함하는 지연이 아니다.
- `tracking_lost`: 현재 자세를 확정하지 못해 마지막 지도와 발견 위치를 보여줄 때 true.

미리보기 `points`는 정적 점 최대 32,000개와 사람 색상 점 최대 2,000개를 전달한다.
기본 예산은 정적 32,000개다. 저장·재생의 점·클래스 검증 상한도 총 34,000개다.
기존 4,000/8,000/10,000점 기록을 계속 읽는다. 최종 재통합에는 유효한 기록 증가 폭을 사용하고,
값이 없는 기록은 첫 유효 정적 관측에서 증가 폭을 계산한다.
숨겨진 호환 정적 점군이나 메시를 중복 생성·전송하지 않는다.
웹의 사람 복셀은 `people`을 사용한다. 전체 사람 모양을 복원하거나 가려진 면을 생성하지 않는다.
웹 점 버퍼는 용량을 재사용한다. 기존 저장 파일의 `mesh`·`meshes`는 계속 읽을 수 있다.

### 사람 발견 위치

| 필드 | 의미 |
| --- | --- |
| `id` | 같은 지도 구간 내 가까운 최근 관측을 연결한 번호. 사람의 신원이나 확정된 인원수가 아님 |
| `center`, `bounds` | 관측한 3D 점의 중심과 축 정렬 외곽 상자 |
| `voxels`, `voxel_size` | 관측 영역의 복셀 중심·크기. 사람당 최대 1,600개 |
| `confidence` | 해당 사람 분할 탐지 신뢰도 |
| `last_seen_s`, `source_frame_id` | 마지막으로 실제 관측한 입력 시각·프레임 |
| `observed`, `age_s` | 현재 프레임에서 관측했는지와 마지막 관측 이후 시간 |

사람 마스크를 약간 확장해 정적 점군에서 제외한다. 사람 복셀은 최근 2초 이내의 관측만 보여주며
그 이후에도 마지막 발견 표식은 유지한다. 현재 관측은 실선, 이전 관측은 점선 외곽선이다.
관측이 끊긴 사람을 예측 위치로 이동시키지 않는다. 이 연결 번호는 재식별 모델을 사용하지 않으므로
장시간 가림·빠른 이동·여러 사람이 교차할 때 중복 발견 위치가 생길 수 있다.

## 기록·최종 결과

각 NPZ에 `semantic_labels`, `semantic_confidence`, `person_instances`, `person_confidences`와
`rescue_json`(UTF-8 JSON을 uint8 배열로 저장)을 추가한다. replay는 당시 표면·사람을 그대로 읽는다.
JSONL 색인에는 큰 점 배열을 반복 기록하지 않는다. NPZ의 의미 미리보기는 12MiB 이하로 검사한다.

최종 통합은 모든 관측을 기록에서 다시 읽어 지도 구간별로 같은 예산의 점군을 만든다.
새 `scene.json.rescue`는 `render_mode=points`이며 `mesh`·`meshes` 필드가 없다.
실제 표시용 `scene.points`와 PLY에는 최근 사람의 색상 점도 포함하며 `points_include_people=true`로 명시한다.
마지막 발견 표식·시점별 사람 정보는 `rescue`와 history에 보존한다.

미리보기와 history 좌표는 native x-right/y-down/z-forward다. 최종 결과는 기존 viewer의
y-up/z-back 변환을 점군·사람 중심·복셀·bounds에 동일하게 적용하고 `display_y_up=true`를 쓴다.
`point_fusion.coverage_bounds`는 native 좌표계의 관측 통계다.
단위는 arbitrary다. 실제 치수 정확도·중력 방향·안전한 이동 가능 공간으로 해석하지 않는다.

이전 메시 결과의 `mesh_revision` 캐시 동작은 읽기 호환으로 유지한다. 새 점 지도에는 적용하지 않는다.

실시간 continuous 정책은 브라우저 표시 확인 없이도 프레임별 복원·기록을 진행한다.
위치 추적 스레드는 제한된 프레임 큐를 통해 최대 15Hz 입력을 계속 처리한다. 깊이·분할은
그중 선택된 후보를 사용하며 아직 선택하지 않은 후보만 최신 것으로 교체할 수 있다.
`tracked_frames`, `mapping_sampled_out`으로 추적 처리 수와 미선택 후보 수를 구분한다.
선택한 복원 프레임의 처리 중 교체는 없으며, 원본 수신과 녹화는 기존 경로를 유지한다.
저장 영상과 이전 API의 sequential 정책은 표시 확인 대기를 유지한다.

## 검증 범위

점군 통합은 NumPy CPU 배열 연산이며 Open3D 의존성이 없다. 모델은 서버 작업 프로세스에서 재사용한다.
프레임별 추적·분할·점군 통합·기록과 화면 주기는
서로 다르며 UI 표시 대기는 continuous 정책에서 추적·입력을 멈추지 않는다.
현재 ORB 추적기 자체에 사람 마스크를 주입하거나 전역 루프 보정 후 과거 자세를 재추정하지는 않는다.
움직이는 다른 가구의 완전한 분리, nvBlox, 센서 변경, 실기체 비행과 실측 정확도는 후속 검증 범위다.
