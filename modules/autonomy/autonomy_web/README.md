# 자율비행 웹 화면

자율비행을 하는 동안 **드론 카메라 영상**, **지도 위 위치·계획 경로**, 비행 단계·기체 상태를 브라우저로 보고,
시작·착륙·비상 정지를 누르는 화면이다. 실기체와 Gazebo 시뮬레이션이 같은 화면을 쓴다.

화면 모양, 이륙 전 점검 신호등, 운용자 확인 체크박스, `Esc` 비상 정지, 온도 경고 기준은
[tello_link 점검·조작 화면](../tello_link/README.md)(`static/index.html`)에서 가져왔다.
그 화면은 사람이 키보드로 조종하고, 이 화면은 자율비행 코드가 조종하는 것을 지켜본다.
둘은 같은 UDP 포트를 쓰므로 동시에 켜지 않는다.

| 파일 | 역할 |
| --- | --- |
| `autonomy_web.py` | ROS 2 노드 + 웹 서버(표준 라이브러리 `http.server`). 토픽을 모아 JSON·MJPEG으로 내고, 버튼을 토픽으로 보낸다 |
| `static/index.html` | 화면 (카메라 · 조작 · 지도 · 위치 · 기록) |

## 화면

| 영역 | 내용 |
| --- | --- |
| 맨 위 띠 | 지금 하는 일과 이유(비행 노드 `/tt/mission_note`, 2026-11-16): `자율 탐색 중 · 남은 탐색 시간 1:20`, `출발점으로 돌아가는 중 · 이유: 탐색 시간(120초)이 다 돼`, `내리는 중 · 이유: …`, `비행 끝 · 내린 이유: …`, `중단 · 이유: …`. 비행 노드가 알리지 않으면 비어 있다 |
| 카메라 | `/tt/camera/image_raw` MJPEG (640px, 초당 10장). [YOLO 탐지] 탭은 `/tt/detections/image`(탐지 노드를 켰을 때) |
| 조작 | [비상 정지 (Esc)] [자율비행 시작 (T)] [착륙 (L)], 높이·하방 ToF·배터리·온도·기수 값(땅에서 흐르면 `(흐름)`과 이유 — 그동안은 비행 노드가 시작을 받지 않는다)·rc·위치 σ, 이륙 전 점검, 운용자 확인 |
| 지도 | `known_map.json`의 벽·가구, 계획 경로(`/tt/path`), 지나온 길, 드론 추정 위치·방향·σ, 목적지. 시뮬레이션은 정답 위치(회색 원)도. 한 번 클릭하면 보낼 자리가 찍히고, 아래 [여기로 보내기 (G)] [지우기·가기 취소]로 보낸다 |
| 위치 | 추정 위치, (시뮬레이션) 정답 위치와 오차, 목적지까지 거리 |
| 기록 | 비행 단계 변화, 버튼, 드라이버의 이륙·착륙 결과, 자동 착륙, 비행 노드가 알린 돌아가는 이유·내리는 이유, 찍은 자리에 대한 답 |

- **[자율비행 시작]**: 비행 노드가 `READY`(위치를 잡고 시작을 기다림)이고 드라이버의 이륙 전 점검을 모두 통과했을 때만 켜진다.
  한 번 누르면 4초 동안 "한 번 더 누르면 이륙"으로 바뀌고, 그 안에 다시 누르면(`T` 키도 같음) `/tt/mission_cmd start`를 보낸다.
  그러면 비행 노드가 드라이버에 이륙을 요청하고 목적지까지 날아가 착륙한다.
  브라우저 확인창(`confirm`)을 쓰지 않는 이유: Claude 앱 안 브라우저에서는 확인창이 막혀 시작이 안 됐다(2026-10-27).
- **운용자 확인 체크박스**: 드라이버에 `/tt/flight_cmd confirm`을 보낸다. 착륙·비상 정지 뒤에는 드라이버가 다시 풀므로 매번 다시 확인한다.
- **[착륙]**: `/tt/mission_cmd land` → 비행 노드가 그 자리에 착륙을 요청한다. 비행 노드가 이미 끝났는데 떠 있으면 드라이버에 바로 `land`.
- **[비상 정지]**: `/tt/flight_cmd emergency` → 드라이버가 모터를 즉시 멈춘다(공중이면 떨어진다).
- **지도에서 찍어 보내기**(탐색 비행 중, 2026-11-11): 지도를 한 번 클릭하면 `보낼 자리`가 찍힌다(끌기는 이동, 두 번 클릭은 처음대로 —
  찍기만으로는 아무것도 보내지 않는다). **[여기로 보내기]**(`G`)를 누르면 `/tt/mission_cmd goto <x> <y>`(지도 좌표, m)를 보내고,
  비행 노드가 그 자리를 다음 볼 자리로 삼는다(막힌 곳·못 본 곳·아직 길이 없는 곳이면 그쪽으로 갈 수 있는 가장 가까운 자리).
  가는 길·회피·문 지나기는 비행 노드가 그대로 하고, 도착하면 둘러본 뒤 자율 탐색을 잇는다.
  비행 노드는 받았는지·가는 중인지·못 가는 이유를 `/tt/operator_goal`(JSON)로 알리고, 화면은 그 글을 기록에 적고 지도에 청록 점으로 그린다.
  마지막 답은 버튼 옆에도 20초 보인다(거절·그만둠은 주황색 — 11/16 15:33 실기체에서 거절 세 번이 맨 아래 기록에만 나와 못 봤다).
  탐색 시간이 다 돼 돌아가는 중에 보내도 비행 노드가 받는다: 다녀온 뒤 다시 돌아간다(11/16).
  **[가기 취소]** 는 `goto cancel`을 보낸다. 버튼은 비행 노드가 받는 단계(PLAN·FOLLOW·REPLAN·LOOK·BACKOFF·HOLD·EXIT·RELOC·DOOR)에서만 켜진다.
- 화면(웹 서버)을 꺼도 비행은 계속된다. 안전 장치(명령 끊김·상태 끊김·배터리·온도 착륙)는 드라이버가 맡는다.

## 시뮬레이션에서

```bash
cd simulation/tt-sim
ros2 launch launch/mission.launch.py world_dir:=$PWD/worlds/s7_stage2 headless:=true web:=true            # YOLO 없이
ros2 launch launch/mission.launch.py world_dir:=$PWD/worlds/s7_stage2 headless:=true web:=true detect:=true
```

Windows 브라우저에서 http://localhost:8080 을 연다(WSL2가 localhost로 이어 준다). 시뮬레이션은 운용자 확인이 자동으로 켜져 있다.

## 시험

웹 서버는 ROS 토픽을 모으기만 하므로 Gazebo로 확인했다(위 명령). 비행 노드의 시작 대기·착륙 요청은 tt-sim 단위 시험에 없다.
지도에서 찍어 보내기는 비행 노드 쪽을 tt-sim 단위 시험(`tests/test_goto.py`)으로, 화면 쪽을 가짜 비행 노드를 붙인 브라우저로 확인했다
(클릭 → 보내기 → 받음 → 가는 중 → 도착 → 탐색 이어감, `G` 키, 취소, 끌기·두 번 클릭은 안 찍힘). Gazebo에서는 시험용 노드가 화면과 같은
명령(`goto <x> <y>`·`goto cancel`)을 보내 5판을 돌렸다(결과는 [tt-sim AVOIDANCE.md](../../../simulation/tt-sim/AVOIDANCE.md) 5절). 실기체로는 아직 날려 보지 않았다.
