## 실제 입력·환경

- 회차 `2f1_20261021`, 원본 PTS 12.0~27.5초, 1920×1080. 원본 영상·31장·DB는 `data/real_data/`에 보존한다.
- 확정 Git snapshot은 `data/mapping/phone_video/2f1_20261021/`이며 원본 수치/해시를 변경하지 않았다.
- 카메라는 사용자 진술 iPhone 13, 1×. 실측 내부 보정 미확인.
  공유 SIMPLE_RADIAL의 초기 `[2304,960,540,0]`를 시작으로 초점/왜곡을 추정하고 주점은 고정했다.
- Windows 11, i7-13700H(14코어/20스레드), 메모리 약 31.6GiB.
  RTX 4050 Laptop GPU가 있으나 이번 PyCOLMAP 실행은 CPU만 사용했다.
- Python 3.12.14, PyCOLMAP 4.2.1, NumPy 2.3.5, SciPy 1.17.0, Pillow 12.3.0.
  스레드 4, 난수 seed 42, DB의 기존 특징점/매칭을 소비했다. 이번에 특징점을 다시 추출하지 않았다.

## 실패를 확인한 뒤 한 차례 입력 조정

| 실행 | 등록 | 점 수 | 평균 점 재투영 오차 | 스케일 | SfM·색상 시간 |
| --- | --- | --- | --- | --- | --- |
| 최초 전체 입력 | 31/31 | 5,299 | 0.544px | 기준점 불일치로 미보정 | 13.28초 |
| 0038 명시 제외 | 30/31(제출 30/30) | 5,362 | 0.501px | 44cm 기준 적용 | 7.74초 |

전체 입력에서 `frame_0038.jpg`(19초)의 카메라 중심은 이전 18.5초에서 임의 단위 약 5.18만큼 급변했다.
나머지 네 시점으로 삼각측량한 같은 A/B를 0038 카메라에 재투영하면 약 1,071/1,289px 불일치했다.
원본 주석 사진에서 같은 문을 가리키는 것을 확인했다. 자동 특징점의 평균 오차가 작더라도 해당 자세를
정상으로 확정할 수 없었다. 반복 사물함·반사면의 잘못된 대응이 가능한 원인이나 정확한 매칭 원인은 미확정이다.

원본 DB/사진/수치 snapshot은 수정하지 않고 `--exclude-frame frame_0038.jpg`로 한 번 조정했다.
그 결과 한 개 연결 모델에 30장이 등록되고, A/B 4시점 관측이 허용 기준을 통과했다.
제외 프레임과 최초 실패 결과는 로컬 로그/출력에 남긴다. 낮은 평균 오차만으로 절대 정확도를 주장하지 않는다.

현재 결과: `output/phone_mapping/2f1_sfm_v3/`.
44cm 기준 scale_factor 약 0.472888, A 최대 재투영 0.566px, B 최대 1.726px.
각 점의 평균 재투영 오차 중앙값 약 0.419px, p95 약 1.167px.
136cm 바닥 C의 다중 시점 동일점은 미확인이므로 스케일·독립 치수 검사에서 제외한다.

## 재실행·인계

설치·복원·검증은 [localization 안내](../../modules/mapping/localization/README.md),
웹 실행은 [console 안내](../../apps/console/README.md),
필드·축·단위는 [결과 계약](../../contracts/mapping/PHONE_SFM_RESULT_V1.md)을 따른다.
회차마다 새 출력 폴더를 사용한다. 생성물에는 입력·코드·출력 해시와 실제 설정이 남는다.
원본 `data/real_data/`와 생성물 `output/`는 Git에 올라가지 않는다.

웹은 로컬 127.0.0.1에서 점군 회전/확대, 카메라 시점·원본 PTS 재생, 색상·오차 표시,
PLY/pose/CSV 다운로드를 제공한다. 실촬영 자료의 외부 호스팅·EC2 배포는 수행하지 않았다.

## 남은 단계

검증: 기하/스케일 4개, 로컬 서버 3개, 기존 수신 입력 6개, 저장소 기존 테스트 15개(협업 양식 포함)를 통과했다.
생성 결과의 독립 PLY/pose/변환 검사와 JavaScript 구문·Git 공백 검사도 통과했다.
실제 브라우저에서 점군 표시, 원본 이미지 1920px 로드, PTS 슬라이더·재생, 오차 필터(1px 이하 4,932점),
색상 전환, 위 시점·카메라 시점 전환을 확인했다. 가로 넘침과 브라우저 오류/경고는 없었다.

- MR 실제 병합 전에는 Jira 완료로 표시하지 않는다. 사용자가 push/MR 후 대기를 요청했다.
- 상대 담당자가 결과 계약과 파일을 읽는 실제 수신 확인은 아직 없다.
- 공개 샘플 기준 실행, 같은 영상 재실행 비교, 독립 길이 관측 확보와 치수 평가를 후속으로 진행한다.
- 현재는 희소 점군이며 고밀도 점군·표면 메시·텍스처 복원은 수행하지 않았다.
  장면의 없는 면을 임의로 채우지 않았다. 이후 밀집 복원은 가용 CUDA COLMAP 환경과 촬영 시차를 별도 확인한다.
- 드론 전환에는 실제 렌즈 내부 보정, 원본 PTS/디코더, 단안 스케일, rolling shutter/흐림,
  위치 상실·재방문·처리 시간, 실제 센서 좌표 정합을 다시 검증한다. 현재 결과는 오프라인 휴대폰 PoC다.

근거: [COLMAP 공식 복원 절차](https://colmap.github.io/tutorial.html),
[PyCOLMAP API](https://colmap.github.io/pycolmap/pycolmap.html).
