# Jira 작업 작성 convention

프로젝트: S15P31B205 / 사이트: https://ssafy.atlassian.net.
기존 담당 이슈가 같은 범위라면 새로 만들지 않고 재사용한다. 이 양식은 에이전트·사람이
작성할 때 참조하는 저장소 문서이며 Jira 웹 UI에 자동 등록되는 템플릿은 아니다.

## 제목·필드

- 제목: `[분야] 구체적인 작업`. 예: `[INFRA] 에이전트 협업 규칙 적용`.
  분야는 INFRA, BE, FE, AI, DATA, COMMON 중 선택한다.
- 작업 유형: 일반 구현은 프로젝트의 작업 유형을 사용한다. Epic은 여러 작업을 묶을 때만 사용한다.
- 담당자: 실제 작업자. 에이전트 자신의 계정이나 알 수 없는 사용자로 임의 지정하지 않는다.
- 상위 항목·스프린트·기한: 기존 계획과 확인된 값으로 지정하고 추측하지 않는다.
- 실제 발급된 Jira 키만 브랜치·커밋·MR에 사용한다.
- 자동 생성 이슈도 제목의 분야·담당자와 아래 본문의 완료 조건·검증 내용을 보완한다.

## 이슈 설명 양식

아래 양식을 실제 내용으로 채운다. 기존 이슈에 내용을 보완할 때는 원래 요구사항과 첨부를 보존한다.

```markdown
## 목적
해결할 문제와 필요한 이유

## 작업 범위
- 구현하거나 변경할 내용

## 완료 기준
- [ ] 확인 가능한 결과 또는 동작

## 검증 방법
실행할 검사와 기대 결과

## 관련 자료
관련 명세·문서·MR 링크. MR이 아직 없으면 생성 후 추가한다.
```

완료 기준은 '개발 완료'처럼 모호하게 쓰지 않고 관찰할 수 있는 결과로 작성한다.
Jira 접근이 없으면 양식에 맞춘 내용을 사용자에게 전달하거나 승인된 MR 자동 등록 흐름을 사용한다.
에이전트의 저장소 지침만으로 Jira 필드 작성을 서버에서 강제하지는 않는다.
