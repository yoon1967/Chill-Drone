# 시스템 아키텍처 초안

작업: [S15P31B205-9](https://ssafy.atlassian.net/browse/S15P31B205-9).
버전 0.2 / 2026-10-22. 사용자 요청에 따라 Jira를 근거로 작성한 선행 설계다.
사용자가 초안을 먼저 정하도록 지정했으므로 아래 기본안을 사용해 병렬 구현을 시작한다.
초안 문서는 검증 후 develop에 반영하며, 구현·실물 종단 검증 결과는 별도 작업에 기록한다.

## 0. 먼저 적용할 기본안

| 결정 | 초안 기본값 | 선택 이유·변경 경계 |
| --- | --- | --- |
| 이번 주 시연 | 휴대폰 녹화 RGB → 프레임/2D 관측 → 희소 3D 점군·카메라 경로 → 로컬 미리보기·스케일 평가 | 드론·GPU·웹 구현을 기다리지 않고 지도 PoC 진행 |
| 계산 위치 | 복원·학습·추론·ROS/Gazebo는 각 파트 로컬. EC2는 현행 상태 웹과 향후 경량 결과 저장·조회 | 제공 EC2의 CPU 자원을 장시간 계산과 분리 |
| 공통 연결 | 버전 0.1.0의 JSON manifest + PLY 점군 + JSON pose, run_id로 회차 격리 | 언어·프레임워크와 독립적으로 파일로 먼저 연결 |
| 후속 웹 | 로컬에서 만든 결과를 올려 회차 목록·점군·경로·평가·탐지 이벤트를 조회 | 서버가 원본 영상 복원 작업을 실행하는 기능은 후속 확장 |
| 저장 | 원본/전체 결과는 생산자 로컬 비공개 경로. 웹은 검토된 결과만 SQLite 메타데이터 + 전용 파일 볼륨 | 초기 단일 서버·낮은 쓰기량 기준. 다중 쓰기/서버 확장 시 재검토 |
| 공개 | 코드·명세·직접 만든 합성 예제부터 공개 준비. 원본 영상·가중치·실측 결과는 비공개 기본값 | 공개 전 각 자료의 이용 조건 확인 |

구체적 필드·경로·오류·크기 제한은 [공통 연결 초안](../../contracts/POC_V0_1.md)에 정의했다.
[합성 결과 묶음](../../data/samples/poc-v0.1/README.md)으로 소비자를 먼저 만들 수 있다.
기존 담당자의 작업·스프린트는 유지하며 웹 화면 구현자가 배정되기 전에는 샘플로 연결한다.

## 1. 현재 구현되어 실행 중인 인프라

~~~mermaid
flowchart LR
  U["브라우저"] -->|"HTTPS 443"| C["EC2 Caddy"]
  C -->|"호스트 loopback 18065"| W["상태 웹 컨테이너 18066"]
  H["호스트 상태 수집 timer"] -->|"선택 필드 snapshot"| F["읽기 전용 상태 폴더"]
  F --> W
  G["GitLab develop"] --> V["격리 검증 Runner"]
  V --> B["보호 배포 Runner"]
  B -->|"SHA 이미지와 Compose"| W
  G -->|"기존 Webhook"| J["Jira 완료 상태"]
~~~

Jira 완료는 develop 반영이고 실제 배포 성공은 파이프라인/환경에서 별도 판정한다.
현재 EC2 앱은 상태 웹이며 실제 BE·DB·3D 화면이 이미 배포됐다는 뜻이 아니다.

## 2. 이번 주 휴대폰 3D 복원 흐름

~~~mermaid
flowchart LR
  A["휴대폰 녹화 RGB 영상"] --> D["촬영·프레임·PTS·manifest"]
  D --> M["2D 특징점·매칭·실측 관측"]
  M --> K["SfM/COLMAP·카메라 pose·3D 점군"]
  K --> S["임의 스케일과 실측 보정·평가"]
  S --> P["회차별 결과 묶음·저장·재실행"]
  P --> R["로컬 미리보기·품질 확인"]
  I["입력·좌표·스케일 계약 초안"] -.-> D
  I -.-> K
  I -.-> P
~~~

- 박수경: 영상/프레임·2D 좌표·매칭·실측 관측, 결과 묶음·저장·미리보기·오류 샘플.
- 김수호: 공통 입력·좌표·스케일 계약, 기준 환경, 3D 복원·카메라 경로·스케일/품질 평가.
- 필수 경계: run_id·frame_id·원본 PTS·해상도/회전·카메라 정보 출처·입출력 버전.
  필드·타입·DB/CSV 역할은 공통 연결 초안의 기본값을 사용한다. 실제 전달 검증은 기존 계약 구현 작업에서 수행한다.
- 보정 전 길이는 임의 단위, 보정 후에도 별도 실측 검증이 필요하다. 깊이·IMU·정답 pose·ROS를
  이번 주 휴대폰 입력의 필수 조건으로 추가하지 않는다.
- 작은 합성 예제로 양쪽을 병렬 개발하고 실제 입력의 수신·재로딩으로 연결을 검증한다.

## 3. 탐지·시뮬레이션·향후 웹 연결

~~~mermaid
flowchart LR
  CAM["휴대폰·녹화·가상 카메라"] --> INF["사람 탐지 추론·중복 억제"]
  INF --> E["사진·클래스·신뢰도·시각 이벤트"]
  TRAIN["별도 데이터·라벨·학습·평가"] -.->|"검증된 모델 버전"| INF
  SIM["로컬 ROS 2·Gazebo"] --> AUTO["경로 계획·비행 제어"]
  SIM -->|"가상 관측·정답/추정 구분"| MAP["지도·위치 추정"]
  HW["향후 실제 TT 어댑터"] -.-> AUTO
  MAP -.-> PACK["회차별 지도·카메라 경로"]
  E -.-> API["향후 BE 저장·조회 API"]
  PACK -.-> API
  API -.-> UI["향후 결과 확인 화면"]
~~~

점선은 연결 계획 또는 교체 경계다. 실제 비행 제어나 미구현 API를 EC2에서 이미 제공하지 않는다.
허병우의 시뮬레이션·제어, 송승우의 추론·탐지 이벤트, 이수진의 휴대폰 영상·재난 조건 데이터/모델 평가를
기존 Jira 분담에 따라 표시했다. 윤병현의 이전 센서/지도 계획과 문서 역할은 현행 분담과 겹치는 부분을 확인해야 한다.
API는 박수경 담당 기존 백로그, 화면의 현재 구현 담당은 미배정이다.
후속 구현의 기본 스택은 Python/FastAPI API와 React/TypeScript/Vite + Three.js 화면으로 제안한다.
이 문서의 역할 표는 실제 담당자를 새로 배정하거나 해당 앱을 설치했다는 기록이 아니다.

## 4. 실행 위치·책임

| 실행 위치 | 책임 | 현재 확인 수준 |
| --- | --- | --- |
| 각자 로컬 작업 공간 | 프레임/복원·학습·추론·시각화 코드, 비공개 원본 | Jira 계획/부분 수행 기록. 전체 소스 통합 재현 미실행 |
| 로컬 ROS 2/Gazebo | 가상 기체·센서·비행 제어, 실제 어댑터 교체 | 기준 환경 완료 이슈 존재. 현재 저장소 패키지 구현은 미확보 |
| 제공 EC2 | CI·HTTPS·상태 웹·향후 경량 API | 현재 상태 서비스와 배포 경로 실측 검증 |
| Jira/GitLab | 계획·담당/상태와 코드·MR·검증 | 기존 Webhook 및 develop 자동 배포 실행 확인 |
| 향후 비공개 데이터 저장 | 원본·가중치·큰 결과는 생산자 로컬, 웹 결과는 전용 파일 볼륨 | 초안 기본값. EC2 외부의 독립 백업 목적지는 아직 확보하지 않음 |

## 5. 구현 순서·확인할 결과

1. 지도 데이터는 원본 좌표/PTS와 회차 manifest를 만들고, 복원 파트는 같은 run_id의 점군·pose·축척 결과를 낸다.
2. 양쪽은 합성 결과 묶음으로 독립 개발한 뒤 실제 영상 1회차를 수신·재로딩한다. 실제 시험 결과는 각 구현 이슈에 기록한다.
3. 화면은 합성 결과의 회차 목록·상세·점군·경로·단위·부분 실패 표시부터 만든다. BE는 같은 파일의 저장·조회부터 만든다.
4. 탐지 파트는 프레임 기준 이벤트를 파일로 먼저 전달한다. 2D 탐지만으로 3D 사람 위치를 생성하지 않는다.
5. 시뮬레이션·실기체는 별도 어댑터로 이어 붙인다. 정답 pose와 추정 pose를 다른 출처로 유지한다.

초안 완료는 위 기본값·흐름·책임·계약·합성 예제의 문서화와 develop 반영이다.
파트별 최종 합의 회의, 실제 모델 성능, 실기체 비행, 웹 앱 배포를 수행한 것으로 표시하지 않는다.
실제 구현과 차이가 생기면 이 문서와 계약 버전을 함께 갱신한다. 확인할 빈칸을 이유로 초안 반영을 대기하지 않는다.
기존 [폴더·병렬 작업 경계](../team/REPOSITORY_STRUCTURE.md)와 [운영 구성](../EC2_CICD.md)을 따른다.
