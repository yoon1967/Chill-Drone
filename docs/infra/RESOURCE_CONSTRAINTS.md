AWS 계정 식별자·인스턴스 ID·사설 주소·키·토큰은 기록하지 않았다.

클라우드 방화벽 허용 범위는 사용자가 제공한 운영 안내를 근거로 하며 AWS 콘솔에서 보안 그룹을
직접 확인한 값은 아니다. 실제 외부 서비스 노출은 호스트 UFW·Docker 규칙과 구분한다.

## 부하 배치와 제한

- EC2는 상태 웹·HTTPS·가벼운 서비스·CI를 우선한다. 현재 앱 제한은 128 MiB/0.5 CPU,
  프록시는 256 MiB/0.5 CPU다. 이 수치는 설정 상한이며 호스트의 예약 용량 보장은 아니다.
- CI와 서비스가 같은 4 vCPU·메모리를 공유한다. 대규모 COLMAP 복원·모델 학습·영상 전체 처리를
  배포 서버에서 무제한 병행하지 않는다. 파트별 로컬 자원에서 먼저 실행·계측하고 필요 시 작업을 분리한다.
- T3는 CPU 크레딧을 사용하는 유형이다. 장시간 최대 성능·추가 요금 없음은 보장하지 않는다.
  크레딧 잔량·Unlimited 설정·청구액은 현재 접근 범위에서 확인하지 못했다.
- 현재 단일 EC2이므로 인스턴스 장애에 대한 고가용성은 없다. 앱 배포 실패 복구는 전체 서버/DB 복구와 다르다.
- 파일시스템 여유량은 계속 변한다. 원본 영상·프레임·점군·가중치는 Git에 넣지 않고 회차별 크기와 보존 기간을 정한다.
  필요한 이전 배포 이미지를 지우는 자동 prune은 설정하지 않는다.

| 제약 | 현재 대안 | 추가 결정 조건 |

| 단일 서버·단일 디스크 장애 | 저장소로 재구성, 앱 이전 버전 복구, 별도 비공개 데이터 보관 계획 | 백업 대상·주기·복원 시험·RPO/RTO 확정 |
