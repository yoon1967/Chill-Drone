# Chill-Drone 실행기 (`scripts/start.cmd`)

프로젝트를 켜는 실행 파일은 `scripts\start.cmd` 하나다. 더블클릭하면 메뉴가 두 개 뜨고, 고른 쪽의 기능을 **묻지 않고 모두** 켠다.
명령줄에서는 `scripts\start.cmd fake` 또는 `scripts\start.cmd real`. 내용은 이 폴더의 Python 모듈(`python -m apps.launcher`)이다.
매핑 계측 도구는 [modules/mapping/benchmarks](../../modules/mapping/benchmarks/)에 있다.

| 메뉴 | 명령 | 켜는 것 |
| --- | --- | --- |
| 1 체험 | `start.cmd fake` | 가짜 드론 게이트웨이(8030) + 사람 탐지 + 가짜 지도(8795)·지도 연결기 + 영상 복원용 지도 콘솔(8796) → 관제 화면 `#/live`. 드론 없이 화면을 볼 때 |
| 2 실기체 관제 | `start.cmd real` | 실기체 게이트웨이(8010) + 사람 탐지 + 지도 콘솔(8790)·지도 연결기 + **지도 자동 시작** + MoNA 자율 → 관제 화면 |

켜기 전에 빠진 패키지·모델 파일·지도 콘솔 웹 의존성(pnpm)을 확인해 받는다(인터넷 필요, 다 있으면 몇 초). 못 받은 것이 있으면
그것이 필요한 프로그램만 빼고 켠다.

메뉴 1·2의 **지도 콘솔**(관제 화면 `#/map`)에서 영상 드롭, 최근 복원, 저장 결과의 3D 지도 편집을 쓴다.
드론 없이 이 흐름을 보려면 1(체험)을 켠다(영상 복원용 콘솔 8796). [지도 콘솔 안내](../console/README.md#지도-콘솔과-영상-폴더)

## 실기체 관제(`real`)

1. 드론을 켜고 PC를 드론 Wi-Fi(`TELLO-…`/`RMTT-…`)에 연결한다. 연결 전이어도 게이트웨이는 켜지고, 드론이 붙으면 알아서 연결된다.
2. 8010 포트나 드론 UDP 포트(8889·8890·11111)를 다른 프로그램(점검 화면 `check_server.py`, 다른 게이트웨이, 직접 연결 지도)이
   쓰고 있으면 켜지 않고 그 프로그램을 보여 준다. Tello는 처음 `command`를 보낸 쪽에만 답하기 때문이다.
3. 게이트웨이, 사람 탐지, 지도 콘솔·지도 연결기를 각자 창으로 띄운다. 기록은 `data/outputs/tello/`.
4. **지도:** 영상이 켜지면(화면의 "영상 켜기" 또는 이륙하면 자동) 실행기가 지도 콘솔에 Tello 지도 세션을 시작하고 2초마다 유지한다
   (`mapkeeper.py`). 지도 콘솔 화면만으로는 게이트웨이 모드 지도를 시작할 수 없어서 실행기가 대신 한다. 설정은 콘솔 화면 기본값과 같다
   (인명 구조 지도, 깊이 384, 32,000점, 초당 5장, 콘솔의 Tello 내장 보정값). 점군은 관제 화면 3D 칸과 `#/map` 안쪽 **실시간 지도** 탭에 보인다.
   - 영상이 30초 안에 돌아오면 같은 지도가 이어진다. 더 길게 끊기면(배터리 교체·재부팅) 콘솔이 세션을 끝내고(지도는 콘솔
     기록에 남는다) 영상이 다시 켜질 때 새 지도를 시작한다. 관제 화면 3D 칸도 새 지도로 바뀐다.
   - 지도 콘솔에서 "드론 연결 해제"·"촬영 종료"로 지도를 마무리하면 저장할 수 있게 그대로 두고, **다음 이륙이나 영상을 껐다 켤 때**
     새 지도를 시작한다. 콘솔에서 직접 시작한 지도가 돌고 있으면 기다린다.
   - 지도 시작이 연달아 세 번 실패하면(Docker 꺼짐 등) 더 시도하지 않는다. 다른 지도가 돌거나 정리 중인 것은 실패로 세지 않는다.
   - **지도 콘솔의 "1. 드론 연결"(드론 검색·Wi-Fi 연결·현재 네트워크에서 드론 확인)은 누르지 않는다.** 드론은 게이트웨이가 쥐고 있어서
     포트 오류가 나고("다른 드론 수신 프로그램을 종료" 안내가 떠도 게이트웨이를 끄지 않는다), Wi-Fi 연결은 PC Wi-Fi를 바꿀 수 있다.
     지도가 돌기 전(이륙 전)에는 콘솔이 "드론 해당 없음"으로 보이는 게 정상이다.
5. **MoNA 자율:** 드론이 붙으면 MoNA 창을 띄운다(Docker·MoNA 이미지·깊이 모델이 있을 때). 비행 모드라 이륙 뒤 화면에서 "자율"을
   눌러야 기체를 움직인다.

`--phone`을 붙이면 게이트웨이를 같은 망에 열고(`--host 0.0.0.0`) 폰 주소를 알려 준다. 인증이 없으니 같은 망 시험에서만 쓴다.
방화벽 규칙은 보안 설정이라 실행기가 만들지 않고, 필요한 명령만 보여 준다(관리자 PowerShell에서 직접 추가·삭제).

## 끄기 (실행기 창에서 Enter)

실행기 창은 열어 둔다(지도 유지). **Enter를 누르면 모두 끈다.**

- 켜져 있는 게이트웨이의 상태를 먼저 읽어, 실기체가 이륙·비행·착륙 중이면 아무것도 끄지 않고 다시 기다린다.
- 땅이면 지도 세션을 끝내 저장하고, MoNA 컨테이너 → 사람 탐지 → 지도 연결기 → 가짜 지도 → 지도 콘솔 → 게이트웨이 순으로
  각 창에 Ctrl+C를 보내 정상 종료시킨다(게이트웨이가 회차 `metrics.json`과 영상 조각을 마무리한다). 안 끝나면 강제로 끈다.
- 실행기 창을 그냥 닫으면 켠 프로그램은 각자 창에서 계속 돌고, 지도는 45초 뒤 멈춘다(콘솔이 유지 신호를 기다림).

## Python 환경

`scripts\start.cmd`는 이 checkout의 `.venv`, 없으면 main worktree의 `.venv`, 그것도 없으면 환경 변수 `CHILL_DRONE_PYTHON`의
Python을 쓴다. 처음에는 `.venv`만 만들면 나머지는 1·2번이 켤 때 받는다.

```powershell
py -3.12 -m venv .venv
```

실기체 게이트웨이는 이 Python이 방화벽에서 UDP 수신(8890 상태, 11111 영상)을 허용받아야 한다. 규칙이 없으면 `real`이 추가 명령을 알려 준다.
모델 파일만 따로 받으려면 `.\.venv\Scripts\python.exe -B -m modules.mapping.data.prepare_models --download`.
