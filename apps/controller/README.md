# 실내 탐색 관제 화면

드론 감독·탐색 결과·현장 조작 화면이다. 팀원 작업물(사람 탐지, 지도, 자율 비행, 드론 상태)이
프로젝트 목적인 **실내 탐색·사람 탐지·3D 지도**에 맞게 한 화면에 모이도록 자리를 잡았다.

화면은 두 가지로 동작한다.

| 동작 | 여는 방법 | 상단 표시 | 버튼 |
| --- | --- | --- | --- |
| **실시간** | 드론 게이트웨이(`gateway_server.py`)가 내준 주소 | 가짜 Tello / 실기체 | `/ws/drone`으로 **실제 명령을 보낸다** |
| 샘플 | 정적 서버로 열거나 주소에 `?sample` | 샘플 데이터 | 보내지 않는다. 샘플 값은 실측이 아니다 |

지금 실시간으로 채워지는 칸은 상태줄, 조종 줄, 영상, 상세 상태, 비행 기록, 발견 목록(사람 탐지)이다.
지도(자율 비행 위치 추정)는 아직 연결 전이라 실시간에서는 빈 칸으로 안내만 한다.

사람 탐지(실시간): 탐지 프로그램이 게이트웨이 영상을 받아 결과를 `POST /api/detections`로 보내면 화면에 나온다
(형식 `contracts/perception/PERSON_DETECTION_EVENT_V1.md`, 흐름은 `modules/autonomy/tello_link/README.md`).
- 발견 목록: 사람이 보이는 동안을 발견 하나로 묶은 카드. 대표 사진(신뢰도 최고 장면, 누르면 크게), 처음 본 시각, 최대 인원, 장수.
  탐색 결과 화면에는 그때 드론 모드·높이도 적는다. 화면을 새로 열면 `GET /api/detections`로 그동안의 발견을 불러온다.
- 영상 위 윤곽선: 최근 탐지의 사람 윤곽선(`polygons_px`)과 신뢰도를 1초 동안 그리고 탐지 지연(ms)을 적는다. 탐지 결과는 실시간 영상보다 늦게 온다.
- 새 발견이면 "사람 발견" 알림을 10초 띄운다(드론은 멈추지 않는다). 발견 칸 머리에 탐지 동작 중·끊김·연결 전과 초당 처리 장수.
- 드론 없이 보기: `gateway_server.py --fake` → 화면에서 영상 켜기 → `fake_detector.py`(합성 사람).

## 실행

Windows에서는 `scripts/start_autonomy.cmd`를 더블클릭하면 서버와 브라우저가 함께 열린다.
저장소의 `.venv` Python을 사용하며 추가 패키지 설치는 필요 없다.
창을 열어 둔 채 사용하고, 종료할 때는 `Ctrl+C`를 누른다.
포트가 사용 중이면 `scripts\start_autonomy.cmd --port 8891`로 바꿀 수 있다.
브라우저를 자동으로 열지 않으려면 `--no-browser`, 옵션 안내는 `--help`를 사용한다.

허병우 팀원의 별도 자율비행 웹 서버는 `scripts/start_team_autonomy_docker.cmd`(Docker) 또는
`scripts/start_team_autonomy_wsl.cmd`(WSL ROS 2)로 실행한다. 기본 주소는 `http://localhost:8080`이다.
팀원 브랜치의 웹 ROS 노드를 실행하며 비행 드라이버·미션은 별도로 시작한다.
설치·연결·옵션은 [실행기 안내](../../docs/autonomy/WEB_LAUNCHERS.md)를 따른다.

빌드 과정 없이 정적 파일만 쓴다. 저장소 루트에서:

```powershell
# 실시간: 가짜 Tello로 조작까지 (실제 Tello는 --fake 없이)
python modules/autonomy/tello_link/gateway_server.py --fake
# 브라우저: http://127.0.0.1:8010/

# 샘플: 화면 구성만 보기
python -m http.server 8791 --bind 127.0.0.1 --directory apps/controller
# 브라우저: http://127.0.0.1:8791/  (상단 "상황" 목록으로 자율 탐색·사람 발견·통신 약해짐 등을 바꿔 본다)
```

### 조작 (실시간)

| 하는 일 | PC 감독 화면 | 폰 현장 조작 |
| --- | --- | --- |
| 이륙 | "주변 비움·가드·안전 담당 확인" → 이륙 → 확인 창 | 주변 확인 → 이륙 → 확인 창 |
| 이동 | W/S 앞뒤, A/D 좌우, ↑/↓ 높이, ←/→ 회전 (누르는 동안만) | 오른쪽 조이스틱 좌우·앞뒤, 왼쪽 조이스틱 회전·상하 |
| 착륙 | 착륙 버튼 또는 L | 착륙 버튼 |
| 비상 정지(모터 즉시 정지) | 버튼 0.6초 길게 또는 Esc 0.6초 길게 | 버튼 0.6초 길게 |
| 영상 켜기·끄기 | 영상 칸 오른쪽 위 버튼 | (없음. 이륙하면 자동으로 켜진다) |

- 손을 떼거나, 창을 벗어나거나, 게이트웨이 연결이 끊기면 조종 입력은 0이 되고 기체는 제자리에 멈춘다.
- 이륙 전 점검(SDK, 상태 수신, 배터리, 온도, 주변 확인)은 조종 줄에 ✓/✗로 보인다. 하나라도 ✗면 이륙하지 않는다.
- 자율 시작은 PC 감독 화면에서만 할 수 있다. 자율 비행이 아직 연결되지 않아 지금은 잠겨 있다.
- 상태가 10Hz로 바뀌어도 바뀐 칸만 다시 그린다. 영상, 조이스틱, 길게 누르는 중인 비상 정지가 갱신 때문에 끊기지 않는다.
- 이륙 전 점검에서 막는 항목은 ✓/✗, 알리기만 하는 항목(온도 75°C 이상)은 !로 보인다.
- 영상은 게이트웨이를 켜도 자동으로 켜지지 않는다. 지상에서 영상을 켜 두면 기체가 1분에 약 16°C 뜨거워지기 때문이다(10/28 실기체).
  이륙하면 자동으로 켜지고, 지상에서 30초 넘게 켜져 있으면 경고, 60초가 되면 게이트웨이가 끈다. `--no-video`로 띄우면 버튼이 잠긴다.

### 폰으로 열기

게이트웨이를 `--host 0.0.0.0`으로 띄우고, 관리자 PowerShell에서 같은 망에서만 8010을 연다(시험 뒤 규칙 삭제).

```powershell
New-NetFirewallRule -DisplayName "Drone gateway 8010 (test)" -Direction Inbound -Protocol TCP -LocalPort 8010 -RemoteAddress LocalSubnet -Action Allow
Remove-NetFirewallRule -DisplayName "Drone gateway 8010 (test)"   # 시험이 끝나면
```

PC는 드론 Wi-Fi, 폰은 USB 테더링으로 PC와 잇고 폰 브라우저에서 `http://<PC 테더링 주소>:8010/#/control`을 연다.
아직 인증이 없어 같은 망의 누구나 조작 화면에 들어올 수 있다.

### 실기체 확인 (2026-10-28, Tello EDU + 확장 키트, 폰 조작)

| 항목 | 결과 |
| --- | --- |
| 연결 | 폰(USB 테더링) → 게이트웨이(PC, 드론 Wi-Fi) → Tello. 폰 화면 "실기체" 표시, 조이스틱 축 값 지상 확인 |
| 이륙 → 착륙 | 주변 확인 → 이륙(응답 8.9초) → 약 42초 비행 → 착륙(응답 3.8초) |
| 조이스틱 | 사람 rc 480개, 네 축(앞뒤 214·좌우 61·상하 255·회전 255) 모두 사용, 최대 30. 손을 떼면 데드맨으로 0(24개) |
| rc 전송 | 평균 62ms(약 16Hz), 최대 66ms. 첫 수동 비행(10/23)과 같은 간격 |
| 높이 | 하방 tof 최고 1.20m일 때 `h`는 최고 0.40m. `h`를 믿기 어렵다는 허병우 10/27 관찰과 같다 |
| 온도 | 61 → 72°C (영상 끔) |
| **배터리** | **이륙 전 52 → 47%(2분), 이륙 뒤 2초마다 1%씩 줄어 착륙 후에도 같은 속도로 14%까지.** 지상에서도 같은 속도라 실제 소모보다는 배터리 상태(노후·충전 부족) 또는 기체의 잔량 추정 문제로 보인다. 다른 배터리·완충 상태로 다시 확인 필요 |

## 화면과 사용자

| 화면 | 주소 | 누가, 언제 | 가장 크게 보이는 것 |
| --- | --- | --- | --- |
| 실시간 감독 | `#/live` | 운용자, 비행 중 (PC) | 영상 + 탐지 상자, 발견 목록, 지도. 조종은 아래 한 줄 |
| 탐색 결과 | `#/review` | 운용자·보고 담당, 임무 후 (PC) | 발견마다 확인·오탐, 지도 위 발견 지점, 3D 지도, 비행 기록 |
| 현장 조작 | `#/control` | 드론 옆 보조 인원 (폰) | 큰 버튼, 조이스틱, 비상 정지(길게). 자율 시작은 없음 |

정보 우선순위(실시간 감독): ① 안전·조종 주체(상단 상태줄) ② 급한 알림(사람 발견, 통신 약함) ③ 무엇이 보이나·어디 있나(영상·발견·지도)
④ 개입(조종 줄) ⑤ 세부 수치(영상 아래 한 줄).

실시간 감독은 **모니터 한 화면에 스크롤 없이** 들어간다(가로 1100px·세로 700px 이상, 1366×768과 1920×1080에서 확인).
왼쪽은 영상, 오른쪽 위는 발견 목록, 오른쪽 아래는 지도이며 각 칸은 창 크기에 맞춰 줄어든다. 발견이 많으면 목록 안에서만 스크롤된다.
이보다 작은 창과 폰에서는 위에서 아래로 쌓이고 페이지가 스크롤된다.

## 칸별 데이터 출처

각 칸 제목 옆 점선 표시가 그 칸을 채울 작업물이다.

| 칸 | 들어올 데이터 | 형식 | 생산 |
| --- | --- | --- | --- |
| 상태줄, 조종 줄, 상세 상태 | `drone_state` | `contracts/api/DRONE_CONTROL_V0_1.md`(초안) | 드론 게이트웨이, 기체 제어 |
| 영상 | MJPEG `/video.mjpg` | 같은 문서 5장 | 드론 게이트웨이 |
| 탐지 윤곽선, 발견 목록 | WS `detection`, `GET /api/detections`, 사진 `/api/detections/<event_id>.jpg` | `person-detection-event/1.0` (`contracts/perception/`) | 사람 탐지 → 드론 게이트웨이 |
| 지도 경로, 현재 위치 | `pose`, `path` (map 좌표, m) | `contracts/api/AUTONOMY_BRIDGE_V0_1.md` 4장(초안) | 자율 비행 |
| 3D 지도 | 점군·카메라 경로 | `contracts/mapping/VIEWER_SOURCES_V1.md` (`apps/console`) | 지도 |

- **발견 지점은 사람 위치가 아니다.** 탐지 시각에 가장 가까운 드론 위치를 찍는다(실시간은 위치 추정 연결 전이라 모드·높이만). POC 4장대로 `object_position`은 null이며
  2D 상자나 카메라 위치를 사람의 3D 위치로 쓰지 않는다.
- 3D 지도는 지금은 `apps/console`(기본 `http://127.0.0.1:8790/`)을 새 창으로 연다. 화면 안에 넣는 방식은 지도 쪽과 정한다.
- 확인·오탐 표시는 지금 브라우저 메모리에만 있다. 저장 위치(회차 폴더 또는 백엔드 API)는 연결 단계에서 정한다.

## 아직 계약에 없는 것 (화면 자리만)

| 항목 | 화면 | 다음 단계 |
| --- | --- | --- |
| 통신 품질 `link`(단계, 상태 Hz, 응답 ms, SNR) | 상태줄 "통신 좋음/약함", 통신 약함 알림 | 통신 품질 측정 작업에서 계약에 추가 |
| 비행 시간 `flight_time_s` | 상태줄, 탐색 결과 | 게이트웨이 상태에 추가 |
| 출발점 복귀 `return_home` | 점선 버튼(누르면 안내만) | 자율 비행 쪽과 되짚기 방식 합의 후 |

## 동작 규칙

- 지금 받을 수 없는 버튼은 `drone_state.allowed`에 따라 흐리게 보이고, 누르면 이유만 알린다.
- 비상 정지는 0.6초 길게 눌러야 한다. 긴장한 상태에서 잘못 눌러 공중에서 모터가 멈추는 것을 막는다.
- 사람 발견 시 드론을 자동으로 멈추지 않는다. 알림 옆 "여기서 멈추기"로 운용자가 정한다(오탐마다 멈추면 탐색이 진행되지 않는다).
- 모르는 값은 "없음"으로 표시하고 지어내지 않는다.
