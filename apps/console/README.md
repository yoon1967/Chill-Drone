# 운영·결과 확인 화면

## 지도 콘솔과 영상 폴더

실시간 지도 저장 API는 영상 연결 중에도 현재 회차의 처음부터 요청 시점까지를 별도
`output/phone_mapping/saved_<시각>_<id>/`에 저장한다. 반복 요청은 각각 새 누적 저장본을 만든다.
실시간 깊이 지도는 요청 시점에 처리가 끝난 관측 전체를 합성하고, 진행 중인 장면은 다음 저장에 포함한다.
저장 실패·지도 일부 처리·시각 대응 누락은 상태에 표시하며 원본 녹화는 계속된다.
실시간 감독의 저장 버튼은 후속 UI 연결을 통해 `POST /api/live/checkpoint` 및
`GET /api/live/checkpoint-status`를 사용한다. 두 진행 중 변경을 함께 반영한 뒤 서버를 재시작해야 한다.

`scripts/start.cmd`의 메뉴 1(체험), 2(실기체 관제)에서 **지도 콘솔**을 열면 영상 드롭과 최근 복원부터 나온다. 메뉴 2는 실시간 지도 점군을 실시간 감독에도 늘 보낸다.
MP4·MOV·AVI·MKV를 드롭 영역에 놓거나 선택한 뒤 **카메라 위치 모델**과 **영상 깊이 모델**을 고른다.
선택한 모델이 PC에 없으면 **모델 다운받기**를 누른다. 두 모델이 준비되면 **영상 복원하기**로 시작한다.
위치 모델은 ORB-SLAM3, DPVO, ORB-SLAM3 + DPVO, DPV-SLAM, DPV-SLAM++, ViSTA-SLAM 중 고른다.
ORB-SLAM3는 CPU로 실행되고 다른 위치 모델에는 NVIDIA GPU와 Docker의 GPU 지원이 필요하다.
DPVO, 결합 방식, DPV-SLAM, DPV-SLAM++의 기본 이미지는 CUDA 컴퓨팅 기능 8.6 이상을 대상으로 한다.
영상 복원은 기본 5 FPS로 자세와 깊이를 차례대로 처리한다. 자세와 깊이 기준을 잡으면 복원 중 화면에 현재 프레임과 점군이 갱신된다.
DPVO·DPV-SLAM 계열과 ViSTA-SLAM은 영상 처리가 끝나면 최종 보정한 카메라 경로를 저장 점군에 반영한다.
ViSTA-SLAM은 복원당 최대 4,096개의 위치 추정 입력 프레임을 처리한다.
결합 방식은 ORB-SLAM3로 추적하고, 검증된 DPVO 자세로 짧은 추적 공백을 보완한다.
깊이 및 ViSTA-SLAM 가중치는 `data/models/reconstruction/<모델>/<버전>/`에 보관하며, 준비된 Hugging Face 캐시도 재사용한다.
위치 모델의 선택 목록에는 모델 파일 용량이 표시된다. 최초 설치 시 Docker 이미지와 실행 패키지도 내려받으며, 진행률은 완료한 빌드와 다운로드 단계 기준이다.
아래 **최근 복원**에서 최근 시도와 저장 지도를 다시 연다.
**영상 폴더 열기**는 Windows 탐색기를 연다. 기본 위치는 이 작업의 녹화·지도 회차가 저장되는 `output/phone_mapping/`이며,
회차별 영상은 `live_<id>/recordings/`에 있다. **폴더 변경**에 이미 존재하는 로컬 폴더의 전체 경로를 입력하면 다음 실행에서도 사용한다.
**기본 위치로**로 돌아갈 수 있다. 변경하는 값은 열기 바로가기이며 드론 영상 저장 위치는 위 기본 폴더를 사용한다.

## 3D 지도 편집 UI 초안

복원 완료 화면이나 저장 결과에서 **3D 지도 편집**을 누르면 해당 결과가 열린다. **실시간 감독 → 지도 → 3D 점군**의
**3D 지도 편집**은 게이트웨이에 가장 최근에 도착한 점군을 한 번 읽는다. 게이트웨이가 표본을 보냈다면 받은 점 수와 전체 점 수를 표시한다.
편집 화면은 별도 탭에서 열리므로 관제 탭으로 돌아가 실시간 지도를 계속 확인할 수 있다.

| 위치 | 현재 초안 | 다음 단계 후보 |
| --- | --- | --- |
| 상단 | 출처, 회차·버전, 단위, 편집 PLY 내보내기 | 이름이 있는 편집본 저장과 버전 전환 |
| 중앙 | 회전·이동·확대, 전체 맞춤, 촬영 경로와 원본 토글, 자르기 상자 미리보기 | 정면·평면 보기, 다각형 선택, 기준점·거리 표시 |
| 도구 패널 | X/Y/Z 범위, 안쪽·바깥쪽 유지, 적용, 실행 취소·다시 실행, 점 수 비교 | 이상점 제거와 복셀 간격 조절, 주석 레이어, 구간 정렬 |

원본 범위에 대한 0~100% 좌표로 자를 상자를 지정한다. 예를 들어 X 최대를 70%로 줄이고 **상자 안쪽**을 선택하면
X축 끝부분을 덜어낸 결과를 미리 볼 수 있다. **자르기 적용**을 눌러 확정한 결과를 PLY로 받는다.
현재 PLY에는 좌표와 RGB가 들어간다. 촬영 경로와 복원 이력은 복원 ZIP에서 관리한다. 편집 작업의 실행 취소 내역은 열린 탭 안에서 유지된다.

| 공식 참고 | 화면과 기능에 반영할 점 |
| --- | --- |
| [CloudCompare 대화형 분할](https://cloudcompare.org/doc/wiki/index.php/Interactive_Segmentation_Tool) | 선택 영역의 안쪽·바깥쪽을 남기고 결과를 확인한 뒤 적용하는 순서를 채택했다. 다각형 선택을 추가할 때 회전 모드와 선택 모드를 구분한다. |
| [Open3D 이상점 제거](https://www.open3d.org/docs/latest/tutorial/geometry/pointcloud_outlier_removal.html) | 복셀 다운샘플링과 통계·반경 이상점 제거 후보를 비교할 때 제거 전후 점 수와 영향을 받은 위치를 함께 보여준다. |
| [Potree 프로젝트](https://github.com/potree/potree) | 대규모 웹 점군을 위한 참고다. 편집본에 적용하는 점군 범위와 렌더링에 사용하는 표본을 분리한다. |
| [CloudCompare ICP](https://cloudcompare.org/doc/wiki/index.php/ICP) | 서로 다른 촬영 구간을 합칠 때 기준 구간과 이동 구간을 명시하고 변환 결과를 먼저 비교한다. |

기존 저장 결과와 게이트웨이 점군은 읽는 단계에서 좌표·RGB·촬영 경로를 편집기 형태로 변환한다. 자르기와 PLY 출력은 이 형태에만 적용한다.
편집본을 다시 여는 기능을 추가할 때는 원본 회차·버전·구간과 연산 순서를 별도 편집 문서에 기록하는 구조가 적합하다.
스케일이 보정되지 않은 지도에는 임의 단위를 표시한다. 거리 측정을 넣을 때는 스케일의 출처와 신뢰도를 함께 표시하고, 구간 정렬은 미리보기와 사용자 확인을 거친다.

## 저장 영상의 빠른 복원

저장 지도 탭에서 영상을 선택하고 **빠른 복원 · 영상과 지도 함께 보기**로 시작한다.
모델 준비가 끝난 뒤 프레임을 순서대로 읽으며, 처리한 영상과 누적 지도를 나란히 표시한다.
한 프레임의 위치 추적 → 깊이 추정 → 점군 반영 → 기록 저장 → 화면 표시를 마친 뒤 다음 프레임으로 넘어간다.
원본 영상 미리보기는 복원 시작 시 멈춘다. 영상의 원래 시각은 보존하되 원속도 재생을 기다리지 않고,
처리가 느리다는 이유로 다음 선택 프레임을 버리거나 위치 추적을 앞서 진행하지 않는다.
완료 전에도 회전·확대할 수 있고 완료 후에는 **저장 지도 열기**로 전체 경로의 통합 결과를 연다.
모바일에서는 영상 위, 지도 아래로 배치한다. 기존 SIFT/SfM 경로는 복원 방식에서 선택한다.

저장 영상 자동 복원은 [DPVO GPU 이미지](../../modules/mapping/localization/README.md#저장-영상의-dpvo-보조-추적)가 준비된 PC에서
원본 프레임을 ORB-SLAM3와 DPVO에 함께 전달한다. ORB-SLAM3가 위치·방향을 확인한 프레임에서는
그 자세와 깊이 배율을 사용한다. 최근 여러 프레임에서 이동 방향·배율·회전이 일치하면, 추적 공백 중 최대 1초 동안
DPVO의 자세를 같은 지도 좌표에 적용한다. 정렬 근거가 부족하거나 DPVO를 실행할 수 없으면 이전 관측과 이동 예측을 이용한다.
DPVO가 보완한 프레임은 복원 화면과 결과 경로에서 구분하며, 깊이 복원 대상은 기본 초당 5프레임이다.

빠른 복원 화면은 현재 지도 구간의 전체 누적 지도를 최대 12,000점의 표본으로 렌더링한다.
시간 경과나 40,000복셀 초과로 앞부분을 지우지 않으며 촬영 중에도 누적된 공간을 볼 수 있다.
화면에 표시하지 않은 자료도 삭제하지 않는다. 처리한 각 프레임의 깊이·색상·카메라 내부값·확정
자세·지도 구간 번호를 `history/frames/*.npz`에 별도로 기록하고, `history/index.jsonl`에
영상 시각과 프레임 번호를 남긴다. `manifest.json`에는 좌표계와 통합 방법을 기록한다.
영상 처리가 끝나면 기본으로 **전체 경로 통합 → 전체 지도 저장**을 실행한다. 모든 관측의 깊이를
내부값으로 역투영하고 `world_from_camera`로 변환해 같은 지도 구간의 점을 공간 복셀로 통합한다.
최종 지도는 화면의 12,000점 표본 제한 없이 통합한다. 과거 기록은 당시의 표시 범위로 재생된다.
전체 경로의 복원 관측과 카메라 경로를 저장하고 초기화 대기만으로 부분 복원으로 분류하지 않는다.
공간 복셀 간격은 구간의 첫 관측에서 고정하며 모든 픽셀이 아닌 4픽셀 간격으로 표본을 통합한다.
서로 다른 `map_id`는 좌표 정렬 전에는 합치지 않는다. 모든 구간의 전체 점군을 `submaps/full-*.json`에
보존하고 가장 많은 프레임이 연결된 구간을 기본으로 표시한다. 미정렬 구간이나 단일 관측만 있는
결과는 실제 제한을 표시하며, ZIP으로 모든 구간을 내보낼 수 있다.
건너뛴 입력이나 자세 추적 실패 프레임에는
복원 깊이가 없으며, 관측 기록은 실제 복원한 프레임만 포함한다.

**복원 시각** 슬라이더 또는 **이동할 시각 → 이 시각으로**로 원하는 초로 이동한 뒤
**재생**하면 해당 시점부터 영상과 당시 지도를 함께 다시 볼 수 있다. 배속·일시정지를 지원하며
**최신 복원으로**를 누르면 현재 처리 화면으로 돌아온다. 과거 재생 중이거나 화면이 숨겨진 동안에는
최신 프레임의 화면 표시를 기다리며, 최신 화면으로 돌아오면 순차 복원을 이어간다.
완료 후 저장 지도를 다시 열어 **복원 과정 다시 보기**로 같은 기록을 확인할 수 있다.
**전체 복원 기록 다운로드**는 복원 완료 후 제공하며 재생 자료와 통합용 관측을 함께 ZIP으로 내보낸다.
복원 완료 후 받은 ZIP에는 최종 지도·카메라 경로·촬영 프레임·복원 이력이 함께 들어 있다.
첫 화면의 **촬영 영상이나 복원 기록 ZIP을 여기에 놓으세요** 영역에 그대로 놓거나 **영상·ZIP 선택**으로
선택하면 새 복원 설정 없이 결과 지도를 바로 연다. **복원 과정 다시 보기**에서 원래 영상 시각으로 이동하고
재생한 뒤 **저장 지도 열기**로 돌아올 수 있다. 가져온 기록도 다시 다운로드할 수 있다.
다른 PC나 서버 재시작 뒤에도 묶음 안의 상대 경로를 사용하며, 원래 PC의 절대 이미지 경로는 사용하지 않는다.
기록 기능 도입 전에 만든 결과에는 과거 관측이 없으므로 새로 복원해야 한다.
전체 경로 통합 기능 이전 결과는 다시 복원하면 전체 통합으로 저장된다. 공간 전체의 관측 여부와
치수 정확도는 별개이며, 보이지 않은 벽·방·외부 형상을 생성해 완성된 건물로 보장하지 않는다.
기록은 크기가 늘어나므로 디스크 여유가 필요하며, 기록 대기가 밀릴 때 처리한 관측을 버리는 대신
저장을 기다린다. 화면 재생은 과거에 표시한 최대 34,000점(정적 32,000 + 사람 색상 점 2,000)의 표본을 사용하고 원본 깊이는 별도로 보존한다.

인터넷이 연결된 최초 설치 때 `scripts/start.cmd`(1 체험·2 실기체)가 켜기 전에 빠진 패키지와 모델 파일을 받는다. 모델만 받으려면 `python -m modules.mapping.data.prepare_models --download`.
이 준비 명령에서 필요한 패키지가 빠졌을 때 프로젝트 `.venv`에 의존성을 설치하며, PyTorch가 없으면 NVIDIA GPU 감지 시 CUDA 12.8용,
그 외에는 CPU용을 설치한다. 이미 설치된 PyTorch는 유지한다. 깊이 모델은 첫 복원에서 한 번 불러오고
준비 추론을 마친 뒤 같은 서버의 다음 복원에서도 재사용한다. 준비 중에는 영상이 진행되지 않는다.
모델은 전용 복원 프로세스에 유지하며 프레임 결과를 화면 서버에 전달한 뒤 표시 완료를 기다린다.
순차 복원의 NPZ는 압축 대기를 줄이기 위해 무압축으로 저장하므로 기록 용량이 증가할 수 있다.
일반 실행은 캐시에서 확인한 실제 모델 폴더·YOLO 파일을 사용하며 인터넷 조회·자동 다운로드를 하지 않는다.
복원 작업 프로세스도 Hugging Face 오프라인 모드로 실행한다.
최초 준비에는 깊이 모델 약 100MB, 공간 분할 모델 약 15MB, YOLO 약 7MB와 패키지를 받을 인터넷·디스크 여유가 필요하다.
로컬 파일이 없으면 즉시 준비 명령을 안내한다. 패키지 설치가 실패하면 서버를 시작하지 않으며, 모델 준비가 실패하면
복원 오류를 표시한다. 원인을 해결한 뒤 새 복원을 시작하면 모델 준비를 다시 시도한다.
완료 후에는 같은 CMD만 다시 실행하면 된다. 실행 중이던 이전 서버는 직접 종료하고 새 창의 주소를 연다.

## 실시간 입력의 위치 추적과 깊이 복원

**실시간 지도**의 PC/USB 카메라·검증 영상·Tello 직접/중계 입력도 위와 같은 복원 엔진을 사용한다.
모델과 위치 추적기를 준비한 뒤 카메라 프레임을 받는다. 연속 실시간 모드에서는 추적기가
가용 프레임을 카메라 주기에 맞춰 처리하고, 깊이 복원은 설정한 표본 속도로 진행한다.
추적이 밀리면 Tello 수신부의 대기 슬롯에 최신 프레임을 남긴다. 이미 추적이나 복원을 시작한 프레임에는
해당 영상과 자세를 그대로 사용한다. 실제 추적 속도는 수신 빈도와 장비 처리량에 따라 달라진다.
기존 순차 모드는 최대 15Hz 입력과 프레임 표시 확인을 사용한다. 저장 영상과 실시간 입력은
같은 서버의 준비된 깊이 모델을 재사용하며 동시에 복원하지 않는다.
원본 수신 영상과 현재 처리 영상은 다른 시각일 수 있다. 복원 화면에 나란히 표시하는 처리 프레임·자세·지도는 같은 시각이다.

현재 구간의 전체 누적 지도 표시, 프레임별 깊이·자세 기록, 과거 복원 재생과 **최신 복원으로**를 사용할 수 있다.
추적을 잃거나 깊이 배율을 맞추지 못한 동안에는 마지막 유효 지도와 경로를 유지한다.
수정 전 서버를 계속 실행하면 새 화면 파일과 예전 Python 처리가 섞일 수 있다.
화면에 **최근 10초 지도만 표시** 안내가 나오면 촬영 종료 후 기존 서버 창을 닫고 CMD를 다시 실행해
새로 표시된 주소를 연다. 페이지 새로고침만으로 서버 처리 코드는 갱신되지 않는다.
순차 모드에서 과거 기록을 보거나 복원 화면을 숨기면 현재 프레임 표시를 기다리고, 최신 화면으로 돌아오면 이어간다.
복원 화면의 **촬영 종료**는 기존 **수신 종료**와 같이 카메라 트랙과 영상 수신을 해제하고
누적 관측 전체를 통합·저장한다. 과거 기록 재생 중에도 종료할 수 있다. **전체 경로 지도 열기**로 결과를 열고,
**전체 복원 기록 다운로드**로 지도·프레임·깊이·자세·이력을 내보낸다.
원본 녹화까지 포함하려면 기존 **영상·지도·기록 묶음 저장**을 사용한다.
결과는 `output/phone_mapping/live_<id>/reconstruction/`에 저장되며 서버를 다시 켜도 최근 복원 목록에서 열 수 있다.
실시간 지도 시작·종료는 기존 카메라 연결 경로를 사용하며 비행 명령을 추가하지 않는다.

CMD를 사용하지 않고 직접 환경을 준비할 때는 다음 명령을 사용한다. GPU가 없으면 PyTorch 인덱스를
`https://download.pytorch.org/whl/cpu`로 바꾼다.

```powershell
.venv/Scripts/python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.venv/Scripts/python.exe -m pip install -r modules/mapping/data/requirements-stream.txt
```

기존 ORB-SLAM3 **위치·방향 추정 로직**을 새 영상에 다시 실행한다. 과거 이동 경로 파일을 가져오지 않는다.
RGB 프레임 → ORB 자세 추적 → 같은 시각의 자세 확정 → 깊이 추정 → 고정 자세로 복원 순서다.
깊이로 카메라 자세를 다시 최적화하지 않는다. 초기화·추적 실패 프레임은 깊이 추정을 건너뛴다.
단안 SLAM 좌표와 AI 깊이의 배율이 다르므로, 현재 추적점의 카메라 깊이로 깊이 배율만 맞춘다.
위치·방향은 프레임 처리 시점의 상대 추정이며, 후속 SLAM 최적화나 절대 위치 측정을 보장하지 않는다.
새 지도 구간은 앞 구간과 임의로 합치지 않고 `submaps/`에 별도로 보존한다.

촬영 전 모델 준비에는 선택한 지도 해상도의 깊이·사람·공간 인식 첫 추론도 포함한다.
CUDA에서는 위치 추적 대기 중 약0.75초 이상 간격으로 준비용 깊이 추론을 실행하여 오래 쉰 GPU의
재시작 지연을 줄인다. 준비용 입력은 지도·사람 발견·복원 기록에 추가하지 않는다. CPU에는 적용하지 않는다.
빈 실시간 결과·일시적 응답/이미지 오류 중에도 마지막 유효 점군과 화면 그리기를 유지한다.
추적이 새 좌표계에서 시작되면 화면 시점을 다시 맞추고, **지도 구간**에서 앞 구간을 다시 열 수 있다.
앞 구간을 보는 동안에도 새 구간의 추적·기록은 계속된다. **현재 구간 따라가기**로 복귀한다.
좌표가 연결되지 않은 구간을 하나의 공간에 겹쳐 그리지는 않는다.
상세 원인·계측과 남은 한계는 [실시간 지도 연속성](../../docs/phone_mapping/live-map-continuity.md)을 참고한다.

Docker Desktop과 현재 코드로 빌드한 `ssafy-orbslam3:local`이 필요하다.
실행기는 이 이미지를 빌드하지 않는다. 직접 준비한다:

```powershell
docker build -t ssafy-orbslam3:local modules/mapping/localization/orbslam3
```

SIFT DB·일괄 쌍 매칭·정밀 재투영 검증·PNG 보고서를 실시간 경로에서 실행하지 않는다.
자세 추적 표본은 원본 시각 기준 최대 15Hz, 기본 복원 표본은 최대 5Hz이다. 실제 처리 속도는
계산·저장·화면 표시 완료 속도에 따라 달라진다. 같은 구간의 지도 복셀을 누적하며 화면 전송은 최대 12,000점으로 제한한다.
지도 메모리와 이력 용량은 촬영한 공간에 따라 증가한다.
웹 화면은 새 스냅샷을 기다려 바로 받고 렌더링 후 표시 완료를 서버에 알린다.
화면의 계산 시간은 현재 프레임의 복원 계산이며, 추적 포함 시간은 해당 프레임의 위치 추적 시작부터다.
모델 준비와 웹 전달·화면 표시 시간은 이 계산 수치에 포함하지 않는다.
실측 정확도는 검증되지 않았으며 결과의 좌표 단위는 단안 SLAM의 임의 단위다.
추적점 깊이와 모델 깊이의 배율이 35% 이내로 일치하는 점이 최소 8개·60% 이상일 때만
깊이를 합친다. 일관성이 부족한 프레임은 마지막 지도를 유지하며 다음 관측을 기다린다.
위치 추적에 실패한 프레임은 합치지 않고 마지막 지도를 유지한다. 깊이 복원 단계에서 전역 재정합을
하지 않으므로 긴 이동에서 누적 오차가 남을 수 있다. 취소·오류 시 마지막 처리 화면은 유지하고 완료 결과로 표시하지 않는다.

휴대폰 영상에서 계산한 실제 희소 점군과 카메라 경로를 확인하는 로컬 웹이다.
이번 복원 작업의 미리보기 구현이며 기존 EC2 상태 화면은 `infra/status/`에 유지한다.

## 설치와 실행

Windows에서는 `scripts/start.cmd`를 더블클릭해 2(실기체 관제)를 고르면 게이트웨이·지도 콘솔·지도 연결기를 함께 켜고, 영상이 켜지면 실행기가 Tello 지도를 시작한다(관제 화면 지도 칸의 3D 점군, 이 콘솔의 **실시간 지도** 탭).
실행기가 로컬 Tello 게이트웨이와 지도 서버를 띄우고, 같은 게이트웨이에서 영상과 센서 자세를 받는다.
실행기는 로컬에서 현재 체크아웃한 브랜치의 코드를 사용하며 원격 브랜치를 자동으로 받거나 전환하지 않는다.
MR을 develop에 머지한 뒤에는 로컬 변경을 정리한 상태에서 `git switch develop`, `git pull --ff-only origin develop`을 실행하고 기존 매핑 서버를 종료한 뒤 같은 CMD를 다시 실행한다. 실행 파일을 별도로 복사하거나 적용할 필요는 없다.
Python·웹 의존성과 로컬 모델은 `scripts/start.cmd`가 켜기 전에 확인해 빠진 것을 받는다(인터넷 필요).
통합 Tello 매핑은 센서 자세를 사용한다. ORB-SLAM3 영상 경로를 사용할 때 Docker Desktop Linux 엔진과 SLAM 이미지를 준비한다.
실행기에 표시되는 `Code folder`가 의도한 워크트리인지 확인한다. 공유 `.venv`의 경로와 실행 코드의 폴더는 다를 수 있다.
외부 게이트웨이와 직접 입력 모드의 실행기는 SLAM 이미지 해시를 검사하고 필요한 경우 빌드한다.
첫 빌드는 드론 Wi-Fi로 전환하기 전에 인터넷이 있는 상태에서 실행한다.
세션 ZIP·세션/결과 폴더·영상·프레임 폴더를 CMD에 드롭하면 저장 지도 탭에서 내용을 확인한다.
저장 지도는 바로 열고 영상·프레임은 확인 후 기존 파이프라인으로 새 복원을 시작한다. 이 경로는 Docker 준비가 필요 없다.
웹의 **저장 지도 → 영상 선택**에서도 같은 처리 경로를 사용한다. **기존 지도 열기**는 로컬 폴더
선택 창을 바로 열며, ZIP은 **지도 ZIP 열기**로 선택한다. 최근 복원 카드는 클릭하면 해당 최종 지도를 연다.
카드에 마우스를 올리거나 키보드 포커스를 주면 우측 하단에 휴지통이 나타난다(터치 화면은 항상 표시).
휴지통은 선택한 관리 기록과 결과 파일을 삭제하고 목록을 갱신한다. 관리 저장소 밖에서 참조한
원본 폴더는 지우지 않고 불러오기 기록만 제거한다. 사용 중인 기록은 삭제할 수 없다. 상세 형식·진행·취소는
[불러오기 안내](../../docs/phone_mapping/importing.md)를 따른다.

저장 지도는 **영상 선택 → 복원 설정 → 공간 복원 → 결과 확인** 순서다. 영상 선택 후
미리보기·해상도·길이를 확인하고 초당 추출 프레임과 카메라 보정 프로필을 지정한다.
확인란을 선택하면 **3D 지도 만들기**가 활성화된다. 복원 중에는 실제 처리 단계와 이 화면에서
경과한 시간을 표시하며, 완료되면 결과를 자동으로 연다. 브라우저 재생을 지원하지 않는 영상도
서버에서 검사·복원할 수 있다.

결과 화면은 지도·촬영 이미지·복원 품질을 제공한다. 지도에서 카메라 위치를 누르거나 촬영 시점
슬라이더를 움직이면 해당 이미지를 확인한다. 부분 복원과 실측 스케일 미보정을 별도로 표시한다.
원본 영상이 있으면 **원본 영상**으로 전환해 독립 재생하거나 내려받는다. 지도와 자동 동기화하지 않는다.
**새 영상 복원**은 현재 결과를 삭제하지 않고 영상 선택 화면으로 돌아간다. 좁은 화면에서는 지도를 먼저,
촬영 이미지와 품질 정보를 아래에 표시한다. 변경 후 기존 CMD를 종료하고 다시 실행한다.

처음 사용하는 카메라는 **실시간 지도 → 새 카메라 연결**을 눌러 촬영한 동영상·여러 사진 또는 PC/USB·드론 카메라 촬영을 선택한다.
전용 단계 화면에서 체크보드를 확인한다. 파일 입력은 장면 조건을 채우면 자동으로 계산·검증하고, 직접 촬영은 장면을 모은 뒤 계산한다. 적용용 JSON과 읽기·인쇄용 PDF를 내려받거나 프로필로 등록할 수 있다.

보정 촬영의 미리보기와 장면 분석은 별도로 갱신한다. 드론 영상은 최신 수신 프레임을 표시하고 이미지 로드 후 100ms 뒤 다시 요청하며, 체크보드 분석은 최소 0.75초 간격으로 최신 장면 하나만 처리한다. 분석이 밀려도 대기 장면을 쌓지 않는다. PC/USB 카메라는 브라우저 원본 영상을 연속 재생하고, 보정 장면 전송은 이전 처리 완료 후 0.8초 간격을 유지한다.
실시간 지도의 **기존 카메라 연결** 카드를 펼쳐 Wi-Fi 검색·선택·연결과 카메라 확인·지도 시작을 진행한다.
왼쪽 단계 가이드는 카드 안의 해당 위치로 이동하며, 지도 준비·종료·실패 후에도 카드를 자동으로 닫지 않는다.
두 지도 탭의 진행 순서는 화면 왼쪽 **진행 순서** 탭에 표시된다. 마우스를 올리거나 클릭·키보드 포커스로 목록을 펼친다.
실시간은 드론 연결 → 카메라 보정·설정 → 지도 생성 → 결과 확인·저장, 저장 지도는 영상 선택 → 복원 설정 → 공간 복원 → 결과 확인 순서다.
현재 단계와 이전 단계만 선택할 수 있다. 이전 단계 이동은 실행 중인 작업을 취소하지 않으며 진행 중·완료된 복원 설정은 읽기만 가능하다.
실시간 지도 화면은 지도 생성을 시작한 뒤 3·4단계에서만 표시된다. 연결·설정 단계에는 빈 지도 화면을 표시하지 않고,
이전 연결·설정 단계로 돌아가면 생성 중인 지도도 숨긴다. 실제 지도 생성은 계속 유지된다.
[카메라 보정 안내](../../docs/phone_mapping/calibration_tutorial.md)에 자료 조건·촬영·검증 순서를 설명한다.

보정 화면의 부모 영역까지 숨겨지는 회귀는 실제 브라우저로 검사한다. 테스트용 서버를 실행한 뒤
Playwright를 사용할 수 있는 환경에서 아래 명령을 실행한다. `MAPPING_PLAYWRIGHT_MODULE`은
Playwright가 프로젝트 밖에 설치된 경우 모듈 경로로 지정하며, 프로젝트에서 import할 수 있으면 생략한다.
서버 URL을 지정하지 않으면 이 브라우저 검사만 생략한다. 검사는 보정 촬영이나 기체 연결을 시작하지 않는다.

```powershell
$env:MAPPING_TEST_URL = 'http://127.0.0.1:8790'
$env:MAPPING_BROWSER_CHANNEL = 'msedge'
node --test apps/console/tests/calibration-layout.browser.test.js
```

원격 develop 머지만으로 다른 PC의 파일이 갱신되지는 않는다. 로컬 develop을 업데이트한 뒤
CMD를 다시 실행한다. 실행 중인 이전 CMD/브라우저 페이지에는 변경이 소급 적용되지 않는다.
실행기 자체는 브랜치를 바꾸거나 git pull을 수행하지 않는다.

검증 환경: Python 3.12.14, Node.js 24.19.0, pnpm 11.25.0, Three.js 0.180.0, Chromium 기반 브라우저.
기본 페이지 제공은 Python 표준 라이브러리를 사용하고, 보정·결과 PDF에는 기존 Pillow/OpenCV 환경을 사용한다. Three.js는 설치 후 로컬에서 제공하므로
뷰어를 열 때 CDN·외부 API에 실제 자료를 보내지 않는다.

저장소 루트에서 [복원 실행](../../modules/mapping/localization/README.md)을 먼저 마친다.

```powershell
pnpm --dir apps/console install --frozen-lockfile
.\.venv\Scripts\python.exe apps/console/serve.py `
  --result output/phone_mapping/2f1_sfm_review --port 8790
```

브라우저에서 `http://127.0.0.1:8790/`을 연다. 서버를 종료하려면 실행 터미널에서 Ctrl+C를 누른다.
`--result`는 complete 또는 partial 상태의 복원 결과 폴더, `--port` 기본값은 8790이다.
단일 영상 실행 회차에서는 그 안의 reconstruction/을 지정한다. partial은 등록률 옆에 부분 복원으로 표시한다. 원본 프레임은 복원 당시 위치를 유지한다.
자료를 옮겼다면 새 위치에서 복원하거나 로컬 전용 `local_assets.json`의 `images_root`를 갱신한다.
원본 사진이 없어도 점군/경로는 열 수 있지만 촬영 키프레임 사진은 표시되지 않는다.
PNG·전체 처리 시간은 [파일 실행 안내](../../docs/phone_mapping/video_pipeline.md)를 따른다.
화면의 복원 소요 시간은 SfM·색상 구간이며 전체 영상→PNG 시간은 회차 루트 timing.json에서 확인한다.

## 지도 저장·Wi-Fi 드론 탐색

**드론 연결 → 카메라 확인 → 3D 지도 생성 시작 → 드론 연결 해제 → 전체 이력 저장** 순서로 사용한다.
실시간 탭은 연결 전 새 카메라 연결 버튼과 기존 카메라 연결 카드를 표시한다. 연결 후 카메라·보정 설정을 열고,
지도 생성을 시작해야 `VIDEO → SPATIAL RECONSTRUCTION` 이하 지도·상태·재생 영역을 표시한다.
저장 지도 탭의 불러오기·결과 조회는 드론 연결 없이 사용할 수 있다.
카메라 영역은 SDK 연결 확인 뒤에만 표시되고, 연결 시 영상 수신을 시도한다. 실패하면 **카메라 확인·재시도**를 누른다.
카메라 영상 확인 후 **3D 지도 생성 시작**을 누르면 보정 프로필 없이도 바로 시작한다. 연결 아래 **보정 프로필 사용**을 켜면 저장된 프로필 선택 또는 JSON 업로드가 나타난다. 실시간 입력에는 별도의 카메라 일치 확인란이 없으며, 선택한 보정값의 형식과 해상도는 검사한다. 이 선택을 끄면 이전에 고른 프로필·업로드 파일은 적용하지 않는다.
**드론 연결 해제**는 드론 영상 입력도 종료하고 마지막 지도 처리를 기다린다. 사용자 해제와 처리 완료가
확인된 뒤에만 **3D 지도 저장** 버튼이 나타난다. 그 전에는 단축키로도 저장할 수 없다.
자동 끊김은 수동 해제로 처리하지 않으며, 연결 해제 버튼으로 마무리한다. 지도가 하나도 생성되지 않았다면
저장 불가 이유를 표시한다. 다시 연결하면 이전 저장 상태를 해제한다. 연결 해제는 앱 통신 종료이며 PC Wi-Fi 자체는 유지한다.
비행 중 수동 조종 입력은 착륙 후 연결 해제하도록 안내한다.

**3D 지도 저장** 또는 **Ctrl+S**(macOS: **⌘+S**)는 종료한 세션의 전체 지도 이력을 ZIP으로 내려받는다.
생성된 모든 지도 버전의 지도·점군·카메라 자세·경로와 타임라인을 포함한다.
실시간 과거 회차를 보고 있어도 최신 버전까지 함께 저장한다.
**저장 자료 불러오기**에서 ZIP을 열면 버전별 타임라인을 다시 볼 수 있다.
저장 파일은 기존 불러오기 형식과 호환된다. 서버의 저장 지도 내보내기는 이력이 없는 단일 결과도 지원한다.
원본 촬영 이미지와 로컬 경로 설정은 포함하지 않는다. 다른 촬영 세션은 별도로 저장한다.
지도 생성 전에는 저장할 지도가 없음을 표시한다. 텍스트 입력 중에는 지도 저장 단축키가 실행되지 않는다.

**드론 검색**을 누르면 버튼 아래 Wi-Fi 목록과 검색 당시의 신호 강도(%)가 표시된다.
연결할 SSID를 **더블클릭**하거나, 선택 후 **Enter** 또는 **선택한 Wi-Fi 연결** 버튼을 사용한다.
일반 Wi-Fi도 목록에 표시하며 Tello / RoboMaster TT 후보를 구분한다. 드론 연결은 SDK 응답까지 확인한다.
화면은 3초마다 연결 상태를 갱신한다. OS 조회는 비동기로 실행하며 PC의 현재 SSID·연결 여부·신호 강도와
드론 SDK 응답을 별도로 표시한다. 신호는 OS의 품질 백분율이며 dBm 측정값이 아니다.
강함(75% 이상)·보통(40% 이상)·약함을 표시하고, 조회 실패 또는 10초 초과 지연 값은 성공으로 표시하지 않는다.
신호 추적만을 위해 드론 명령이나 Wi-Fi 재검색을 반복하지 않는다. 목록 갱신은 드론 검색을 다시 누른다.
Windows는 `netsh`, Linux는 NetworkManager의 `nmcli`를 사용한다. OS Wi-Fi 권한이 필요하고,
Windows는 해당 SSID에 한 번 연결한 저장 프로필이 필요하다. 연결 시 PC Wi-Fi가 전환될 수 있다.
목록에는 실제 검색된 SSID만 표시한다. 검색된 Wi-Fi가 없거나 OS 조회가 제한되면 가상 연결 항목을 표시하지 않는다.
PC를 드론 Wi-Fi에 이미 연결했다면 목록과 분리된 **현재 네트워크에서 드론 확인** 버튼으로 SDK 응답을 확인한다. 이 동작은 Wi-Fi를 전환하지 않는다.
Windows에서 위치 권한 안내가 나오면 **설정 → 개인정보 및 보안 → 위치 → 위치 서비스**를 켜고 다시 검색한다.
SSID 후보만으로 연결 성공을 표시하지 않으며 `192.168.10.1:8889`의 SDK 응답을 확인한다.
다른 제조사·주소·암호 입력·Wi-Fi 프로필 생성은 현재 어댑터 범위 밖이다.

연결 후 **자세히 보기**를 눌러야 자원 패널이 열리고 조회 명령을 보낸다. 배터리·자세·고도·거리·온도·
가속도·Wi-Fi 품질·SDK/TT 확장 응답과 수신된 원시 센서 필드를 구분한다. 미응답은 미지원 확정이 아니다.
카메라 확인은 기존 `av`·OpenCV 수신기로 H.264 영상 수신을 시도하며 최신 JPEG만 표시한다.
자원 상세 패널을 닫아도 카메라 영역은 유지한다. 드론 연결을 해제하거나 새 지도/보정 입력으로 전환하면
자체 영상 수신을 종료하고 포트를 넘긴다.
브라우저가 사라져 프레임 요청이 끊기면 15초 뒤 자체 영상 수신을 종료한다.
기존 직접 영상 입력 중에는 그 연결의 센서·영상을 재사용하며 제어 세션에 조회 명령을 끼워 넣지 않는다.
외부 게이트웨이 전용 입력의 센서 탐색은 지원하지 않으며 기존 입력 화면에서 영상을 확인한다.
비행 명령이나 기체의 Wi-Fi 설정 변경 명령은 보내지 않는다.

## PC 카메라 입력

화면 위 **카메라 보정 프로필**에서 기존 보정 JSON을 등록하고 입력별로 선택·기억·내보낼 수 있다.
실시간 입력과 파일 복원은 같은 목록을 사용한다. 사용법과 로컬 저장 위치는
[보정 프로필 안내](../../docs/phone_mapping/camera_profiles.md)를 따른다.

새 카메라 입력에는 프로젝트 Python 환경의 OpenCV·NumPy와 실행 중인 Docker Desktop이 필요하다.
`requirements-online.txt` 설치는 [온라인 실행 안내](../../modules/mapping/localization/ONLINE.md)를 따른다.
저장 결과 조회만 할 때와 달리 아래 옵션으로 카메라 입력을 켠다.

```powershell
docker build -t ssafy-orbslam3:local -f modules/mapping/localization/orbslam3/Dockerfile modules/mapping/localization/orbslam3
.\.venv\Scripts\python.exe -B apps/console/serve.py --enable-camera --port 8790
```

기존 저장 결과와 함께 보려면 `--result <완료 결과 폴더>`, 이전 카메라 기록도 열려면
`--session <세션 폴더>`를 추가한다. 이미 8790 서버가 실행 중이면 해당 서버의 세션을 종료한 뒤
같은 포트의 서버를 재시작한다. Docker 이미지가 없으면 위 build 명령으로 준비한다.

1. `http://127.0.0.1:8790/#live`의 영상 입력에서 **연결된 카메라**를 고른다.
2. **장치 새로고침**으로 목록을 읽고 카메라를 선택한다. 목록 조회는 권한을 요청하지 않는다.
   권한 전에는 이름이나 장치가 공개되지 않을 수 있으므로 기본 카메라로 시작할 수 있다.
   선택한 장치는 정확한 deviceId로 요청하며 다른 카메라로 자동 대체하지 않는다.
3. **카메라 연결 · 시작**을 누르고 카메라 권한을 허용한다. 마이크는 요청하지 않는다.
   원본 크기, 전송 크기, 카메라의 fps 설정값과 보정 사용 여부가 표시된다. fps 설정값은 실제 처리 성능과 다르다.
4. 무늬가 있는 정지된 공간을 계속 보면서 카메라 위치를 천천히 옮긴다. 영상 수신·정상 추적·3D 생성 상태를
   각각 확인한다. 고정 카메라나 제자리 회전만으로 유효 점군 생성이 보장되지는 않는다.
5. **수신 종료**로 카메라를 해제하고 지도 마무리를 기다린다. 권한 대기·연결 준비 중에도 취소할 수 있다.
   장치를 바꾸려면 종료 후 선택한다. 페이지를 떠날 때도 카메라 트랙과 해당 세션을 정리한다.

영상은 긴 변 최대 960px로 축소하고 JPEG와 media 시각·프레임 순번을 같은 PC의 서버로 전송한다.
인코딩·전송을 하나씩 진행하며 밀린 프레임을 계속 쌓지 않는다. 서버가 종료되거나 세션이 바뀌면
해당 카메라를 해제한다. 취소 뒤 도착한 이전 카메라·세션·프레임 응답은 새 세션에 적용하지 않는다.
권한 거부, 장치 없음·사용 중, 지원하지 않는 장치 설정은 안내를 보고 다시 시도할 수 있다.

**카메라 보정**의 JSON은 현재 렌즈·가로세로 비율·촬영 방향에 맞아야 한다. 다른 휴대폰 영상에서
계산한 값을 웹캠에 재사용하지 않는다. `width`, `height`, `fx`, `fy`, `cx`, `cy`는 유한한 숫자이며
`distortion`을 제공하면 `[k1, k2, p1, p2]` 숫자 4개다. 서버는 같은 비율의 전송 크기에 맞춰 내부 파라미터를
조절한다. 크기·초점거리·주점·왜곡 값이 잘못되면 SLAM 시작 전에 거부한다.
PC 카메라에 파일이 없으면 입력한 수평 화각을 사용하며 **화각 추정 · 미보정**을 표시한다.
Tello 입력은 아래 실측 기본값을 사용한다. 실측 미터 단위나 치수 정확도를 보장하지 않는다.

정상 입력 후 지도가 초기화되기 전에 중단하면 **생성 전 종료**와 빈 점군을 표시할 수 있다.
`complete`는 입력 처리가 종료됐다는 뜻이며 `map_available`로 3D 생성 여부를 따로 확인한다.
추적 상실 뒤 새 지도 segment가 시작되면 이전 지도 점 수와 현재 지도 점 수가 다를 수 있다.
의도적인 렌즈 가림 후 같은 지도로 복귀하는 검증은 휴대폰 영상 시험에서 진행한다.

## Tello 카메라로 실시간 지도 생성

### 실행기로 실기체 지도

1. 노트북을 드론 Wi-Fi에 연결하고 `scripts/start.cmd`에서 2(실기체 관제)를 고른다. 게이트웨이·사람 탐지·지도 콘솔·지도 연결기가 함께 켜진다.
2. 관제 화면에서 **영상 켜기**를 누르거나 이륙하면 실행기가 지도 콘솔에 Tello 지도 세션을 시작하고 유지한다. 점군은 관제 화면 지도 칸의 **3D 점군**과 이 콘솔(`http://127.0.0.1:8790/#live`)의 **실시간 지도** 탭에 보인다. 관제 화면 지도 칸의 **실시간 지도 ↗**가 이 탭을 새 탭으로 연다(관제 화면 `#/map`은 촬영 영상 복원 화면이다).
3. 조작 키와 이륙·정지 조건은 [관제 화면 안내](../controller/README.md#조작-실시간)를 따른다.
4. 착륙 후 실행기 창에서 Enter를 누르면 지도 세션을 끝내 저장하고 모두 끈다(공중이면 끄지 않는다).

게이트웨이 모드(`--tello-gateway`)에서는 드론을 관제 게이트웨이가 쥐고 있어서, 콘솔의 **1. 드론 연결** 칸은 게이트웨이의 드론 연결·배터리·영상을
보여 주고(`/api/drones/state`의 `owner: gateway`·`gateway`), 드론 검색·Wi-Fi 연결·현재 네트워크에서 드론 확인·자세히 보기는 숨긴다.
서버도 이 요청들을 `gateway_mode_owns_drone`(409)으로 거절한다(포트 충돌·PC Wi-Fi 바뀜 방지). 연결 상태 칩은 지도가 돌기 전에도 "게이트웨이 연결"이다.
관제 화면에서 드론 영상이 켜지면 이 칸의 **3D 지도 생성 시작**으로도 지도를 시작할 수 있다(실행기는 이 지도가 끝날 때까지 기다린다).
**지도 마무리**(직접 연결 모드의 "드론 연결 해제")로 지도를 끝내도 드론 연결은 그대로이고, 실행기는 저장할 수 있게 두고 다음 이륙이나 영상을 껐다 켤 때 새 지도를 시작한다.
영상이 30초 넘게 끊겨 세션이 끝나도 영상이 다시 켜지면 새 지도를 시작한다.

실행기는 게이트웨이를 일반 모드로 켜고 지도 콘솔을 `--tello-gateway`로 붙인다(아래 "기존 조종 사이트와 동시에 사용").
촬영용 직접 연결은 아래처럼 `serve.py --enable-tello-map`을 직접 실행한다. 전방 ToF의 큰 점 표시는 확장 키트가 있는 직접 연결에서 확인할 수 있다.

### 촬영용 직접 연결

기본 보정은 `data/mapping/tello/20261028/v1/camera.json`의 TELLO-59FA6D,
960×720 원본 스트림 실측값이다. 매번 파일을 선택하지 않아도 적용되며 세션의
`camera.json`, `camera.yaml`, `settings.json`에 적용값이 남는다. 다른 기체·크롭에는
`--tello-camera <보정 JSON>` 또는 기존 보정 파일 선택으로 교체한다.

일시 입력 중단은 최대 30초 동안 같은 세션에서 복구한다. 직접 수신은 잠깐의
영상 공백을 기다리고 5초간 새 프레임이 없으면 소켓을 정리한 뒤 재연결한다.
중계 입력은 HTTP/MJPEG를 다시 열며 중계 서버의 시작·종료·비행 명령을 보내지 않는다.
복귀한 영상은 같은 증가 시간축으로 제출하며 중단 중의 오래된 프레임을 재사용하지 않는다.
페이지와 서버 사이 연결은 최대 45초 재시도한다. 사용자 종료와 페이지 이탈은 복구를 취소한다.

Tello 지도는 한 세션의 관측을 하나의 미터 단위 추정 지도에 누적한다.
상태 패킷의 속도는 전원 켤 때의 방향을 기준으로 적분한다. 하향 ToF를 기체 기울기에 맞춰
높이로 환산하고 값이 튀거나 범위를 벗어나면 수직 속도를 사용한다. yaw·pitch·roll은
카메라 좌표로 변환한다. 자세는 이미 도착한 상태만 사용해 영상 디코딩 시각에 보간하거나
최대 0.2초 앞까지 외삽한다. 카메라의 초점거리·왜곡에는 보정값을 사용한다.

센서 자세를 받지 못하거나 재연결로 센서 원점이 바뀌면, 최근에 지도에 반영한 영상과
깊이에서 특징을 찾아 기존 좌표의 자세를 복구한다. 위치를 찾으면 같은 지도에 반영한다.
겹치는 특징이 부족하면 최근 확인한 두 자세의 위치·회전 변화와 현재 영상 시각을 사용해
선형 예측하고 같은 지도에 계속 누적한다. 확인된 자세가 하나뿐이면 그 자세를 유지한다.
예측 프레임은 같은 복셀의 확인된 관측보다 우선순위가 낮으며 재정렬 기준으로 사용하지 않는다.
웹 화면과 저장 경로에서 센서 추정, 영상 자세 복구, 선형 예측을 구분한다. 센서·영상 근거가
오래 끊기거나 기체가 가감속하면 예측 오차가 커질 수 있다. 영상과 상태의 하드웨어 동기화 및
실기체 정밀도는 별도로 확인해야 한다.

Tello 실시간 지도는 구조물 점을 같은 공간 격자의 복셀로 누적한다. 시뮬레이션 깊이 화면의
파란 기준점인 3.075 m부터는 점 크기를 기본값의 0.65배로 표시한다. 나머지 영상 깊이 점은
기본 크기다. 전방 ToF와 영상이 일치한 표면은 실측 거리로 보정하고 1.4배 크기로 표시한다.
같은 프레임의 다른 영상 깊이 점도 누적한다. 크기 구분은 실시간·재생·저장 지도에 적용한다.

이전 희소 ORB 세션의 추적 영상은 지도 변환과 별도 작업·100ms 조회로 갱신한다. 이미지 URL은 실제
처리 프레임 ID와 세션을 고정하며, 이미 만료된 프레임을 다른 이미지로 바꿔 응답하지 않는다.
원본 영상과 처리 영상은 서로 다른 시점을 표시할 수 있으므로 처리 시각,
수신→추적 시간, 마지막 처리 후 경과 시간으로 최신성을 확인한다.
이 시간은 드론 촬영 시각부터의 지연이나 입력→지도 표시 지연과 다르다.

수치 오류가 생겨도 마지막 유효 지도는 유지하고 `diagnostics.json`과 `orb.log`에
진단을 남긴다. 고정 ORB-SLAM3 버전의 Sim3 영 회전 나눗셈을 단위 quaternion
계산으로 교체하고 퇴화·비유한 샘플은 거부한다. 새 코드를 적용한 서버와 아래
명령으로 다시 빌드한 Docker 이미지가 필요하다. 기존 실행 중인 서버/컨테이너에 소급 적용되지 않는다.

```powershell
docker build -t ssafy-orbslam3:local modules/mapping/localization/orbslam3
```

실시간 지도 탭의 **Tello · 실시간 3D 지도**는 원본 카메라 프레임을 순차 위치 추적·깊이 복원에
연결한다. **Tello / RoboMaster TT · 사람 탐지**는 별도 탐지 화면이며 지도 생성 입력과 구분한다.
지도 입력은 YOLO를 실행하거나 탐지 상자·윤곽선이 그려진 영상을 사용하지 않는다.

Windows Git Bash에서 실행한다. 기존 프로젝트 Python·Three.js와 Docker 이미지 외에
직접 Wi-Fi 연결에는 `av`, `Pillow`, `opencv-python`이 필요하다. 설치되어 있지 않으면
`./.venv/Scripts/python.exe -m pip install av Pillow opencv-python`로 준비한다.

```bash
./.venv/Scripts/python.exe -B apps/console/serve.py --enable-camera --enable-tello-map --port 8790
```

1. 노트북 Wi-Fi를 실제 드론 AP에 연결한다. 확장 키트 장착 기체는 `RMTT-` 이름일 수 있다.
2. 같은 기체를 사용하는 조종·탐지·SDK 프로그램을 종료하고 사이트를 연다. 직접 입력은
   명령 8889·상태 8890·영상 11111 UDP 소켓을 소유한다. Windows 수신 권한은 기존 기체 운영 설정을 따른다.
3. 실시간 지도에서 **Tello · 실시간 3D 지도 → 드론 연결 · 지도 시작**을 누른다.
   브라우저 카메라 권한 요청 없이 `command`, `streamon`으로 카메라를 연결한다.
   처음에는 초기화 대기다. 모터를 동작시키지 않는 짧은 카메라 이동 시험으로 시차와 점군을 확인한다.
4. **수신 종료**는 이 입력이 켠 영상에 `streamoff`를 보내고 SDK·영상 수신기를 정리한다.
   이 모드에는 이륙·착륙·rc 명령이 없다. 비행 조작은 기존 조종 사이트에서 수행한다.

직접 연결(`serve.py --enable-tello-map`)은 RoboMaster TT 확장 키트의 전방 `EXT tof?`를
자동 조회한다. 카메라와 같은 방향으로 설치한 전방 센서를 가정한다. 0.10 m 이상 1.20 m 미만의
거리 중 영상 수신 시각과 0.2초 이내인 값을 사용한다. ToF를 반영하는 프레임은 전방 센서 범위
안에서 실측과 일치하는 표면을 추가한다. 그 표면에 가까운 영상 복셀은 깊이 방향으로 제한적으로
보정하고 작은 점으로 유지한다. 기체 상태의 하방 ToF는 고도 확인에 쓰인다.

평평한 벽을 정면 약 0.5~1.1 m에서 보면 전방 ToF와 깊이 영상의 대응 표면을 확인할 수 있다.
빔과 맞는 표면 깊이는 그 거리로 보정하고, 전방 ToF 없이 처리한 프레임은 모델의 미터 단위
깊이 추정을 사용한다. 연결 상태와 저장 결과의 `depth_mapping.front_tof_by_map`에서
적용 여부를 확인할 수 있다. 미터 단위 출력과 독립 치수 검증은 별도로 표시한다.

드론 Wi-Fi에는 인터넷이 없다. 의존성·Docker 이미지·깊이 모델이 이미 설치되어 있으면 사이트와 복원은
인터넷 없이 이 PC에서 실행된다. 원격 대화나 다른 인터넷 사용을 병행하려면 유선 LAN 또는
휴대폰 USB 테더링으로 인터넷을 확보하고 노트북 Wi-Fi는 드론 연결에 사용한다.
아이폰 USB 테더링은 Windows의 Apple Devices 또는 iTunes가 필요하다.

브라우저 영상의 ORB-SLAM3 경로를 사용할 때는 드론 Wi-Fi로 인터넷이 끊기기 전에
Docker 이미지와 의존성을 준비한다. Tello 실시간 지도는 센서 자세와 기존 지도 기반 영상 복구를 사용한다.

기존 조종 사이트와 동시에 사용할 때는 **그 게이트웨이만 UDP 수신을 소유**하게 하고 아래처럼 실행한다.

```bash
./.venv/Scripts/python.exe -B apps/console/serve.py --enable-camera --tello-gateway http://127.0.0.1:8010 --port 8790
```

조종 사이트에서 먼저 영상을 켠다. 지도 입력은 같은 PC의 `/api/drone/state`(구형 점검 서버는
`/api/status`)와 `/video.mjpg?mapping=1`에 GET을 보낸다.
현재 게이트웨이는 자세를 JPEG 파트에 붙인다. 자세 헤더가 없는 구형 게이트웨이는 첫
카메라를 원점으로 삼고 영상과 깊이로 위치를 추정한다.
상태 응답에 `front_tof.m`, `valid`, `age_s`가 들어 있으면 유효한 전방 거리도 함께 사용한다.
전방 센서를 조회하지 않는 기본 조종 게이트웨이에서는 영상 깊이의 거리대별 점 크기를 사용한다.
게이트웨이를 끄거나 영상이 꺼짐/1초 이상 오래됨 상태면 지도 입력도 종료된다. 게이트웨이의 지상
장시간 영상 자동 종료도 그대로 적용된다. 다시 시작하면 새 지도 세션을 만든다.
주소는 서버 실행 시 고정한 loopback HTTP origin만 허용하며 리디렉션을 따라가지 않는다.

두 모드 모두 **960×720 원본 비율·24fps 기준 설정**을 사용하며 크기가 다르면 입력을 거부한다.
Tello 렌즈와 이 해상도에 맞는 보정 JSON을 선택한다. 없으면 수평 화각을 추정값으로 사용한다.
직접 입력은 PC 디코딩 수신 시각, 게이트웨이 영상 기록은 중계 수신 시각을 사용한다.
두 시각 모두 PC에서 얻은 값이다.
순번은 중계가 읽은 프레임 기준이며 원시 UDP 손실량을 나타내지 않는다.

탭을 닫으면 해당 세션을 중단한다. 응답 전에 창이 사라지거나 브라우저가 비정상 종료되어도
명시적 heartbeat가 15초 동안 없으면 드론 입력을 정리한다. 숨겨진 탭의 타이머 제한으로도
이 중단이 발생할 수 있다. 마지막 유효 지도는 보존하고 저장 지도는 유지한다.
가짜 게이트웨이가 `source=fake` 또는 `mode=fake`를 보고하면 검증용 영상으로 기록·표시한다.
실제 드론 연결·추적 품질·조종과 동시 실행 성능은 실기체에서 별도 확인한다.

## 화면 사용

복원 진행 화면과 복원 과정 다시보기에는 축 아이콘을 표시하지 않는다. 드래그 회전·휠 확대·이동으로
생성 중인 지도를 살펴본다. 완료된 지도에서 **복원 과정 다시 보기 → 저장 지도 열기**로 여러 번 오갈 수 있다.
최종 지도에는 클릭 가능한 **±X·±Y·±Z 축 표시기**가 있다. 표시기는 현재
회전 방향을 따라 움직이며, 축을 누르면 현재 바라보는 중심과 거리를 유지한 채 해당 축 쪽에서
중심을 바라본다. 수직 축에서는 화면 위쪽 방향도 조정한다. 기존 입체·정면·위에서·전체 보기
버튼은 제거했다. 드래그 회전·휠 확대·이동은 계속 사용할 수 있다.
홀로그램 모드는 결과 화면에 연결하지 않으며 예전 `mode=hologram` 링크도 진입시키지 않는다.
관련 점 간격 자동 분석과 홀로그램 표면 분석을 실행하지 않는다. 아래 홀로그램 관련 기술 설명은
과거 구현 참고이며 현재 사용 흐름에 포함하지 않는다.

- 실시간 탭 우측 상단의 작은 **연결 상태** 상자는 서버 응답·드론 응답·영상 수신·3D 지도 처리를 2초마다 구분해서 표시한다.
  서버에 닿지 않으면 드론은 `확인 불가`이며, 서버가 정상 응답하고 SDK 연결이 실패한 경우에만 `드론 연결 실패`로 표시한다.
  영상 입력 수가 5초 이상 늘지 않으면 `수신 지연`, 추적을 잃으면 `추적 상실`, 종료된 지도는 `기록 보존`으로 표시한다.
  시작 전 드론에 명령을 보내 연결을 점검하지 않으며, 상태 조회 자체는 연결·종료·heartbeat를 보내지 않는다.
  게이트웨이는 중계의 응답을 표시하며 실기체 SDK 연결을 직접 확인한 것으로 해석하지 않는다.
  화면 변경은 새로 연 탭에 적용된다. 진행 중인 입력 탭을 새로고침하면 기존 pagehide 처리로 수신이 끝나므로 시험 종료 후 새로고침한다.
- 상단 **저장 지도**는 `--result`의 고정 실험 결과, **실시간 지도**는 현재 입력 세션 또는 `--session`의 기록을 표시한다.
  기본 탭은 저장 지도이며 `/#live`로 실시간 탭을 바로 열 수 있다. 브라우저 뒤로/앞으로, 탭에서 좌우 화살표·Home·End도 지원한다.
  해당 입력이 없으면 빈 상태를 표시한다. 저장 지도와 실시간 지도를 서로 대신 표시하지 않는다.
- 탭을 바꿀 때 이전 조회를 취소하고 늦은 응답을 무시한다. 같은 지도에 돌아오면 촬영 시점·3D 시점·표현 모드를 복원한다.
  실시간 입력은 탭 전환으로 종료하지 않으며 **수신 종료**로 끝낸다. 브라우저의 비활성/숨겨진 영상 전달 성능은 별도 검증 대상이다.
- 실시간 탭의 **영상 입력 / 특징점 추적 / 3D 지도**를 구분해서 읽는다. 영상 수신만으로 3D 초기화가 끝나는 것은 아니다.
  입력 전·권한 거부·장치 없음·연결 중단·지도 초기화 대기·마지막 유효 지도·완료 기록을 표시한다.
  페이지 열기와 탭 전환은 카메라 권한을 요청하지 않으며, 카메라를 선택하고 시작할 때만 요청한다.
- 드래그로 회전, 휠로 확대, 오른쪽 드래그로 이동한다. 입체·정면·위 시점을 선택할 수 있다.
- 최초 시점은 중심 구조에 맞춘다. 모든 점은 계속 렌더링되며 `전체 보기`는 외곽 점까지 포함해 맞춘다.
- **촬영 시점** 슬라이더는 선택한 지도의 키프레임 사진과 카메라 위치를 연결한다. `이 위치에서 보기`로 해당 카메라 방향을 확인한다.
- 실시간 탭의 별도 **지도 생성 시간** 슬라이더·재생은 실제 기록된 지도 revision을 교체한다. 첫 유효 지도 이전은 빈 점군이다.
  카드에는 최신 지도 상태와 현재 표시 중인 기록 버전·점 수를 함께 표시한다. **최신 지도**로 현재 수신을 다시 따라간다.
- 점 크기·색상·오차 필터, 촬영 경로·카메라 방향·격자를 조절한다. 필터는 표시만 바꾸고 원본 출력을 바꾸지 않는다.
- PLY, 카메라 자세 JSON, 경로 CSV를 내려받아 다른 도구에서 읽을 수 있다.

`reference_scaled`는 44cm 기준으로 맞춘 미터 단위, `arbitrary`는 미보정 임의 단위다.
미터 단위 격자의 한 칸은 0.5m다. 격자 평면은 표시용이며 실측 바닥·중력 방향이 아니다.
표면 메시·독립 치수 정확도·실시간 SLAM을 제공하는 화면으로 표시하지 않는다.

## 접근 범위

서버는 127.0.0.1에만 바인딩하고 정해진 정적 자원, 완료된 결과, 등록된 원본 프레임 이름만 제공한다.
저장소·실제 자료 디렉터리 열람, `.env`, 원본 DB, 로컬 절대 경로 JSON은 제공하지 않는다.
실제 촬영과 복원 결과는 Git·Sites·EC2에 업로드하지 않는다.

## Tello / RoboMaster TT 사람 탐지

드론 Wi-Fi에 PC를 연결하고 영상 수신 의존성을 설치한 뒤 `--enable-tello`를 추가한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r modules/perception/inference/requirements.txt
.\.venv\Scripts\python.exe apps/console/serve.py --tello-only --port 8790
```

사람 탐지 화면에서 안전 조종 패널도 함께 사용하려면 `--tello-flight`를 명시한다.

```powershell
.\.venv\Scripts\python.exe apps/console/serve.py --tello-only --tello-flight --port 8790
```

드론 연결 후 안전 확인을 체크하고 이륙한다. `W/S`는 앞·뒤, `A/D`는 좌·우,
방향키 위·아래는 상승·하강, 왼쪽·오른쪽은 회전이며 `L`은 착륙이다.
`Esc` 비상 정지는 모터를 즉시 멈추므로 충돌 위험일 때만 사용한다.

기존 지도와 드론 영상을 함께 보려면 `--tello-only` 대신
`--result output/phone_mapping/<완료된 결과> --enable-tello`를 사용한다.

화면의 영상 입력에서 **Tello / RoboMaster TT**를 선택하고 **드론 연결 · 탐지 시작**을 누른다.
서버가 SDK `command`, `streamon`을 보내고 UDP 11111의 H.264 영상을 디코딩한다. 기본
`yolo26n-seg.pt`는 최초 실행 시 Ultralytics가 내려받으며 Git에는 저장하지 않는다. 별도 가중치는
`--tello-model C:\\models\\person-seg.pt`처럼 로컬 경로로 지정한다. YOLO는 person 클래스만
추론하며 인스턴스 마스크에서 사람 외곽선을 그린 영상을 `/api/tello/video.mjpg`로 제공한다. 종료 버튼은
`streamoff`를 보내고 영상·명령 소켓을 닫는다. 점검 서버와 동시에 실행하면 UDP 11111 포트가
충돌하므로 둘 중 하나만 실행한다. Windows 공용 네트워크 방화벽에서 Python의 UDP 8890·11111
수신도 허용해야 한다.

입출력은 [복원 결과 계약](../../contracts/mapping/PHONE_SFM_RESULT_V1.md)을 참고한다.
팀 작업 절차는 저장소 루트의 `docs/team/START_HERE.md`를 따른다.

## 공간 표현과 온라인 갱신

[온라인 처리 안내](../../modules/mapping/localization/ONLINE.md)에서 영상 수신과 영상 경계 기반 객체 복원을 준비한다.
웹 자체는 Python 표준 라이브러리와 설치된 Three.js를 계속 사용한다.

`--result <완료 결과> --objects <객체 폴더>`로 저장된 지도에 평면 객체를 붙이고,
`--session <온라인 실행 폴더>`로 수신 중이거나 기록된 지도를 연결한다. 두 입력을 함께 지정할 수 있다.
저장 결과는 `/api/saved/state`, `/api/saved/run`, 온라인 세션은 `/api/live/state`, `/api/live/run`에서
각각 조회한다. 실시간 세션을 새로 시작해도 saved 경로의 결과·단위·이미지·내려받기는 유지한다.
카메라 입력만 받을 때는 `--enable-camera`만으로도 시작할 수 있다.
상단 탭은 [소스 조회 계약](../../contracts/mapping/VIEWER_SOURCES_V1.md)의 saved/live 고정 경로를 사용한다.
이전 `/api/run` 호환 경로는 온라인 세션이 있으면 이를 따라간다.
웹은 2초마다 상태를 확인하고 새 revision만 가져온다. 지도와 객체는 같은 응답으로 읽는다.
갱신 중 사용자의 시점·표현 모드는 유지하며 좌표 segment가 바뀌면 시점을 다시 맞춘다.

- **객체·영상 표면**: 영상 경계와 여러 시점의 특징점으로 확인한 평면 객체에 실제 영상을 입힌다.
- **홀로그램**: 같은 객체의 면을 사진 질감 없이 반투명 발광 격자·스캔 효과·테두리로 표시한다. 원본 점군과 지지점도 확인할 수 있다. 모션 줄이기 설정에서는 스캔 애니메이션을 멈춘다.
- **원본 점군**: SfM 점과 오차 필터를 직접 확인한다.

홀로그램 탭의 **점 좌표 간격**은 지도 점들의 최근접 거리를 최대 256개 표본에서 계산해
소수 자릿수·슬라이더 범위·권장 간격을 정한다. 최근접 거리 중앙값의 자릿수보다 한 자리 더
세밀하게 조절한다(예: 약 0.0029인 지도는 0.0001 단위). 실제 조절 단위와 표본 거리도 표시한다.
숫자로 직접 입력하거나 **권장 간격 적용**을 누를 수 있다.
점 간격·신뢰·구조 표시 HUD는 3D 화면 아래에 배치한다. 넓은 화면은 가로로 나열하고,
좁은 화면은 세로로 쌓아 점군을 가리지 않는다. 홀로그램 버튼을 누를 때마다 조정창을 열고 닫는다. 다른 탭으로 이동하면 즉시 닫고 홀로그램을
다시 누르면 연다. 창을 닫아도 선택한 간격은 유지하며 지도 재생·갱신이 창을 다시 열지 않는다.
간격 3에서는 각 축을 0, ±3, ±6… 중 가장 가까운 값으로 표시한다. 거리가 같은 경우에는 원점에서
먼 쪽을 선택한다. **원본 위치로** 또는 간격 0으로 복원한다. 같은 격자에는 한 점을 표시한다.
입력·저장·내려받기·촬영 경로는 유지하며 홀로그램 표시만 바뀐다. 원본 점군과 객체 모드는 원래
좌표를 사용한다. 재생·지도 갱신·오차 필터 후에도 선택한 간격을 다시 적용한다. 단위는 지도의
스케일을 따르며 단안 임의 단위를 미터로 해석하지 않는다.

그 아래 **신뢰 threshold**는 좌표를 모은 다음 서로 다른 관측 프레임의 합집합 크기를 검사한다.
기본값 3은 최소 3프레임 관측이며 숫자·슬라이더로 조절한다. 같은 프레임의 여러 점은 한 번만
센다. ORB 지도에서는 선택된 **키프레임** 기준이고 전체 처리 프레임 기준이 아니다.
격자 수·원본 점 수·실제 표시 수를 보여주고 만족하는 점이 없으면 빈 점군을 표시한다.
과거 결과에 프레임 연결이 없으면 개별 트랙 관측 수의 최대값만 하한으로 사용하고 격자 합산
불가를 표시한다. 관측 수는 기하 정확도나 사물 분류 확률이 아니다.
조정창은 함께 토글되며 원본 점군 탭에는 격자화·신뢰 필터를 적용하지 않는다.

홀로그램 조정창의 **구조 표시 · 실험**에서 `점만 / 선만 / 선·면`을 비교한다.
`연결 범위`는 주변 점 간격에 대한 연결 거리 배수다(기본 2.5배). 격자에 합쳐진 원본 점의
CIELAB 평균 색상과 색상 편차를 계산하고, 색차가 큰 셀은 연결을 보류한다. `색상 차이 허용`은
Delta E 76 기준 기본 30이며 `이웃 면 꺾임 허용`은 국소 법선의 무방향 각도 기준 기본 55°다.
둘 다 값을 높이면 연결 후보 범위를 넓힌다. 화면의 점 색상 선택은 이 판단에 영향을 주지 않는다.

정렬한 공간 버킷의 이웃 27곳을 조회하고 버킷마다 최대 12개 대표점, 점마다 최대 16개 이웃을
검사한다. 상호 이웃인 점만 그래프 간선으로 사용한다. 연결 비용은 색차·국소 방향 차이·거리·셀 내
색상 편차로 구성하고 Felzenszwalb–Huttenlocher 방식으로 영역 내부 변화와 경계 변화를 비교한다.
최소 군 크기나 반경 내 최소 점 개수를 요구하지 않으며 전체 군의 기준 평면·깊이 잔차도 검사하지 않는다.
국소 방향이 조금씩 변하는 표면은 같은 군으로 이어질 수 있다.

각 점의 최대 16개 이웃을 국소 접평면에 투영해 삼각분할하고 중심점에 닿는 삼각형만 후보로 삼는다.
긴 변·가느다란 삼각형·국소 방향과 맞지 않는 면을 제외하며 한 변에 최대 두 면만 허용한다.
같은 변의 같은 쪽에 겹치는 후보도 제외하지만 전체 면의 교차·완전한 manifold는 보장하지 않는다.
삼각형을 만들기 어려운 영역에는 군을 연결한 최소 신장 숲의 선을 남긴다. 꼭짓점 셀은 서로 다른
두 시점 이상 관측이 필요하고, 공동 관측 두 시점 미만인 선·면은 옅게 표시한다.

버킷·이웃 상한을 고정하면 공간 인덱스와 그래프·면 후보 정렬은 `O(n log n)`이고 후보 생성은
`O(n)`이다. 원본 색상·관측 집계는 별도 입력 크기에 비례한다. 버킷 대표점 제한은 근사 이웃 검색이므로
밀집 영역의 일부 연결을 놓칠 수 있다. 간격 프로파일도 축별 사전 정렬 후 분할해 트리를 생성한다.
구조 표시는 최대 6,000곳을 분석하며 점 표시 수는 줄이지 않는다. 많은 점에서는 셀 키의 고정
해시 순서로 분석 대상을 선택해 새 점이 생겨도 전체 표본이 교체되지 않게 한다.

선·면은 월드 좌표의 고정 블록에 보관한다. 블록 폭은 연결 검색 반경의 16배이고 이웃 검사를
위해 반경 두 배의 halo를 포함한다. 변경된 셀의 이전·현재 위치와 halo에 닿는 블록만 다시
분할하며, 관측 집합만 바뀌면 밝기를, 원본 좌표 모드의 작은 이동은 꼭짓점 버퍼만 갱신한다.
법선과 국소 삼각분할도 제한된 캐시에 보관한다. 블록 경계의 선·면은 꼭짓점 셀 키로 소유자를
하나만 정한다. 전역 FH 결과와 동일한 군집이나 경계의 완전한 manifold를 보장하지는 않는다.
halo를 합친 분석량이 전체 점의 1.1배를 넘으면 캐시를 사용하는 전체 분석 한 번으로 전환해
중복 계산을 피한다. 이때도 변경된 소유 블록만 GPU에 반영한다.

재구성은 Web Worker에서 수행한다. 기존 결과는 새 결과가 올 때까지 유지하고 바뀐 블록의 GPU
버퍼만 교체한다. 최신 요청 하나만 대기시키며, 건너뛴 응답이 있으면 캐시 전체를 재전송해
일부 블록이 누락되지 않게 한다. HUD에 유지·추가·제거한 면, 갱신·재사용 블록, 분석 시간을 표시한다.
세션·좌표계·간격·조건 변경, 역방향 재생, 기준 간격 30% 이상 변화, 30회 갱신마다 전체를 재조정한다.
블록 내부 원본 좌표의 작은 변화는 격자 간격/기준 간격 중 큰 값의 0.2배, 색차는 0.5 ΔE까지
누적 허용한다. 누적량은 마지막 형상 계산 당시를 기준으로 검사한다.

실시간 ORB 지도는 `/api/live/run?since_revision=6자리버전&session=세션&revision=요청버전`으로 추가·수정·제거된 점과
관측만 받는다. 카메라·메타데이터·점 순서는 최신 값으로 보낸다. 기준 버전이 없거나 다른 좌표계,
다른 생산자, 델타가 더 큰 경우에는 전체 snapshot을 받는다. 서버는 저장된 전체 snapshot을
비교하므로 서버 읽기·비교와 브라우저의 snapshot 복원에는 여전히 전체 입력에 비례하는 비용이 있다.
초기 블록 생성과 넓은 좌표 보정에서는 halo 비용 때문에 기존 전역 일괄 처리보다 느릴 수 있다.

점군은 같은 세션·좌표계에서 GPU 버퍼를 유지하고 점 ID로 추가·이동·삭제된 점의 위치·색상만
갱신한다. 삭제는 마지막 표시 슬롯을 옮겨 빈 자리를 채우며 원본 scene의 점 순서와 내보내기는
바꾸지 않는다. 용량은 두 배씩 늘리고 기존 GPU 할당을 해제한다. 전체 snapshot으로 복구할 때도
기존 표시 상태와 비교해 변경된 슬롯만 반영한다. 홀로그램의 격자·서로 다른 관측 프레임 집계도
변경된 점이 속했던 셀과 현재 셀만 갱신한다. 관측별 참조 수를 유지해 점 하나가 제거돼도 다른
점이 지지하는 프레임은 남긴다. 간격·신뢰·오차 필터 변경은 필요한 표시 상태를 다시 계산한다.

정확한 최근접 간격 계산은 별도 Worker에서 최대 2초에 한 번 수행하고 마지막 추천값을 유지한다.
이 계산은 전체 점을 사용하므로 계산량 자체는 점 수에 따라 증가하지만 화면 갱신을 막지 않는다.
선·면 Worker에도 마지막 입력 이후의 변경 점·관측만 보내며 최대 32회 변경 이력 밖으로 밀리면
전체 입력으로 재동기화한다. Worker 내부의 격자·표면 입력 준비는 전체 자료를 사용할 수 있다.
첫 시점 맞추기 이후에는 매 revision 전체 점을 정렬하지 않고 생산자의 경계 정보를 사용한다.
촬영 경로 버퍼도 재사용하고 카메라 자세가 바뀔 때만 갱신한다. 세션·좌표계 변경이나 역방향
재생에서는 표시 상태와 Worker를 새로 만든다. 화면의 모든 가시점은 계속 그리므로 GPU 비용과
전체 지도 저장량의 상한을 보장하지는 않는다.

점군 갱신 검증: `node --test apps/console/tests/point-display.test.js`.

**비슷한 색의 넓은 표면 채우기**는 기존 국소 연결과 별도로 동작하며 체크박스로 비교한다.
신뢰 필터를 통과한 셀의 원본 점과 관측 정보를 재사용한다. 명도 가중치 0.2인 Lab 색차와
유채색의 색조 일치를 이용해 최대 8개 색상 후보를 검사하고, 고정 144회 RANSAC과 PCA로
최대 4개 평면을 찾는다. 특정 초록색이나 화면의 아래 방향을 바닥으로 가정하지 않는다.
최소 12개 원본 지지점과 선 형태가 아닌 2차원 분포가 필요하며, 반경 내 점 밀도는 요구하지 않는다.
평면 오차 한도는 `2.2 × max(원본 최근접 대표 간격, 격자 간격 × 0.1)` 임의 단위다.
이 검사는 넓은 평면 후보에만 적용하며 기존 꺾인 국소 표면에는 적용하지 않는다.

원본 점을 평면에 투영한 convex hull은 채울 수 있는 최대 범위로만 사용한다. 관측 지지가 많은
최대 3개 촬영 시점을 240px 폭으로 읽고, 지지점 세 개 이상이 있는 연결된 색상 영역만 사용한다.
평면 위로 투영한 특징점 좌표에서 사각 패치의 경계를 정한다. 일정 간격의 격자를 그리지 않으며,
원본 특징점의 u/v 좌표가 만나는 위치에 표시용 꼭짓점을 만든다. 네 꼭짓점 모두가 원본 점인 것은 아니다.
사각형마다 들어오는 특징점 수(분할 목표 12개), 색상 편차, 평면 잔차, 가로세로 비율과 영상 경계를
확인하고 필요한 곳을 더 나눈다. 분할 위치도 관측한 특징점 좌표에서 선택하므로 면적은 점 분포에 따라 달라진다.
특징점 convex hull 안에 들어오는 패치만 허용하며, 촬영 영상에 투영한 패치의 모서리와 내부 픽셀을
검사한다. 큰 사각형이 중간의 다른 색 영역을 덮으면 분할하거나 생성을 보류한다.
큰 패치 옆의 작은 패치가 만나는 변도 나눠, 내부 연결을 외곽 경계처럼 강조하지 않는다.
사각형 하나는 두 삼각형으로 그리되 대각선은 표시하지 않는다.
한 시점 일치는 옅게, 두 시점 이상 일치는 밝게 표시한다. 영상이 없으면 넓은 면을 생성하지 않는다.
저해상도 영상에 사라진 가는 구멍·반사·가림과 잘못 추정한 평면을 완전히 구분하지는 못한다.
특징점 범위 밖으로 면을 연장하지 않으며, 채우기용 꼭짓점을 실제 복원 특징점처럼 강조하지 않는다.

전체 입력·관측의 변경 여부를 확인하고, 동일한 입력에서는 넓은 면과 영상 디코딩 결과를 재사용한다.
변경된 입력에서는 이전 평면을 우선 검증하고 기준 평면과 특징점 ID로 고정한 분할 경계를 가능한 한 유지한다.
최대 12개 영상 버퍼를 보관하고, 평면마다 최대 깊이 9·사각 패치 192개·후보 방문 767회의 상한을 둔다.
패치 한도에 가까워지면 영상 검사를 통과한 넓은 패치를 유지해, 개수 제한 때문에 한쪽부터 잘리지 않게 한다.
고정된 후보·반복·분할 상한에서 집계/평면 검사는 입력 크기에 비례하고 정렬과 hull은 `O(n log n)`이다.
영상 처리는 별도 픽셀 비용이며 입력 변경 시에는 넓은 면의 경계·색상 마스크를 다시 검사한다.
첫 분석에는 영상 읽기·디코딩 비용이 추가되고 이후 작업은 Worker에서 수행한다.
저장/실시간 탭을 전환하면 기존 Worker와 표시 캐시를 정리한다. 영상도 해당 출처의
`/api/saved/frame/` 또는 `/api/live/frame/`에서 읽으며, 실시간 요청은 세션·버전을 함께 고정한다.

이 표시는 **색상·기하·영상 관측 기반 후보**이며 사물 종류·실제 접합 여부를 검증한 결과가 아니다.
희소 특징점만 있는 곳은 면이 일부만 생길 수 있고, 미관측 뒤쪽·두께·부피를 임의로 닫지 않는다.
영상 기반 평면 객체와 별개인 로컬 표시 실험이며 원본 결과·다운로드·SLAM 처리는 변경하지 않는다.
새 표시 모듈을 제공하려면 웹 서버를 재시작한다. `/?mode=hologram`으로 홀로그램과 조정창을 바로 연다.
공간 셀 표시와 이전 `--surface` 옵션은 계속 지원하지 않는다.

연결 알고리즘 회귀 검증: 저장소 루트에서 `node --test apps/console/point-surfaces.test.js apps/console/wide-surfaces.test.js`.
차분 API 검증: `python -B -m unittest discover -s tests -p test_console_surface_delta.py -v`.

`공간 안으로 이동`은 선택한 촬영 카메라 위치에서 탐색을 시작한다. WASD 전후좌우, Q/E 상하,
드래그로 시선을 바꾸고 Esc로 종료한다. 화면의 이동 버튼은 모바일에서도 사용할 수 있다.
이것은 시각 탐색 기능이며 벽 충돌·통과 가능·비행 경로의 안전성을 판정하지 않는다.

## 실시간 추적 성능과 종료 진단

현재 실시간 깊이 지도는 위의 순차 처리·표시 확인 경로를 사용하며, 처리 단계와 프레임별 시간이 복원 화면에 표시된다.
native 추적 로그는 `reconstruction/pose_tracker/orb.log`, 깊이·통합 진행은 `reconstruction/progress.json`에 남긴다.

이전 희소 ORB 세션 경로의 지도 내보내기는 최대 초당 1회, 추적 미리보기는 최대 초당 10회로 독립 실행한다.
지도 잠금 안에서는 값만 복사하며 JSON 조립·이미지 저장은 잠금 밖에서 처리한다.
미리보기 JPEG 저장도 추적 스레드에서 분리하고 대기 작업을 최신 1개로 제한한다.
호스트는 변경된 native snapshot만 다시 읽고, 웹 지도 조회 주기는 750ms다.
`tracking_p95_ms`·`input_lag_p95_seconds`는 최근 최대 300프레임 기준이며
`statistics_window_frames`가 표본 수다. 전체 추적 성공률은 계속 누적 기준이다.

상태 조회의 일시 오류만으로 매핑을 자동 종료하지 않는다. 서버의 영상 복구 제한과
클라이언트 heartbeat 제한은 유지하며, 상태 화면 렌더링 오류도 처리 세션을 종료하지 않는다.
종료 요청은 최초 사유를 유지한다. `user_stop`(중단 버튼), `page_hidden`(페이지 이탈),
`client_error`(입력 처리 오류), `browser_media_ended`, `start_cancelled`,
`server_shutdown` 및 서버 입력·추적 오류 사유를 구분한다.
구 클라이언트가 사유를 생략하면 호환을 위해 `user_stop`이 기록된다.

이전 희소 ORB 세션 폴더의 `diagnostics.json`은 정상 종료에도 생성하며 최초 종료 사유와 로그 경로를 담는다.
`events.jsonl`에는 상태 재시도·복구·화면 오류·종료 요청을 최대 512건 남긴다.
`tracking.jsonl`에는 프레임 간격·지도 ID·검출 특징점 수·지도점 대응 후보 수를 기록한다.
`map_candidates`는 기하 최적화가 수락한 inlier 수가 아니다.
`tracking_failures.jsonl`에는 정상 추적에서 상실로 바뀐 시점과 전후 이미지 경로를 최대 512건 남기며,
`diagnostic_frames/`에는 최근 8회분(최대 16장)만 유지한다. 오래된 이벤트의 이미지는 없을 수 있다.
이 진단 자료와 원본 촬영 자료는 로컬에만 보관한다.

CMD를 다시 실행하면 해당 체크아웃의 코드와 일치하는 SLAM 이미지를 준비한다.
이미 실행 중인 서버·브라우저는 다시 시작해야 변경된 서버 코드와 화면 코드를 사용한다.
Docker 기반 이미지는 검증한 Ubuntu digest를 고정해 태그 갱신으로 의존성 캐시가 바뀌는 것을 막는다.

## 원본 녹화와 세션 저장

영상·센서만 공유할 때는 `video_sensor_sync.json`도 함께 전달한다. 이 파일에는 영상 재생 초와
원시 센서 `received_mono`의 시각 대응만 있고, 사진·매핑 선택·카메라 자세는 없다.
`frames.jsonl`과 복원 결과를 공유하지 않아도 팀원이 자기 처리 간격으로 영상과 센서를 연결할 수 있다.
영상 시각이 중복되거나 시각 근거가 빠진 구간은 partial이며 임의 보간/외삽하지 않는다.
기존 종료 회차도 `modules.mapping.data.video_sensor_sync.export_existing_sync`로 생성할 수 있다.

Tello 지도 촬영에는 영상과 같은 `live_<id>/` 폴더에 센서 원시값·수신 시각의 `sensor.jsonl`과
프레임별 입력 여부·센서 자세·최종 카메라 위치/방향·지도 반영 여부의 `frames.jsonl`도 자동 저장한다.
`session.json`에서 파일 목록·좌표/단위·저장 오류를, `settings.json`에서 카메라·매핑·모델 설정을 확인한다.
센서·프레임 로그는 세션 ZIP에도 포함한다. 센서 원시값은 센서 누락이나 저장 실패 시 불완전할 수 있으며
partial 상태로 표시한다. 모델 준비나 처리량 제한으로 제외한 프레임도 입력 기록에 남는다.
이 기록을 이용해 영상을 다시 복원하는 연결은 후속 작업이다. 자세한 형식은
[실시간 세션 계약](../../contracts/mapping/LIVE_SESSION_V1.md#센서와-프레임별-매핑-기록-추가-필드)을 따른다.

실시간 지도를 시작하면 녹화도 자동으로 시작한다. `수신 종료` 뒤에는 영상과 지도 저장을 마칠 때까지
`영상·세션 저장 마무리 중`으로 표시하고, 완료되면 **영상·지도·기록 묶음 저장**으로 ZIP을 내려받는다.
화면의 저장 폴더에도 같은 자료가 이미 있으며 기본 위치는 `output/phone_mapping/live_<id>/`다.

Tello 직접 연결은 `recordings/part_0000.h264`에 수신 원본을 보존하고 종료 후 재생용 MP4를 만든다.
연결을 다시 열면 part 번호가 증가한다. 짧은 끊김이 같은 연결에서 복구되면 한 영상의 시각 간격으로 남는다.
브라우저·게이트웨이는 서버에 전달된 JPEG 영상이며, 장치 원본과 구분해서 표시하고 MKV로 묶는다.
보정값·지도 시계열·키프레임·로그·진단은 같은 세션 폴더에 있고 `session.json`이 파일들을 연결한다.
지도 초기화에 실패해도 원본과 세션 정보를 저장할 수 있다.

녹화는 8MiB로 제한된 별도 큐·작업을 사용한다. 쓰기 오류·큐 초과는 지도 처리 오류와 구분해 표시한다.
원본이 없거나 재생 파일 생성에 실패한 경우에도 진단과 이미 저장한 부분은 남는다.
강제로 창/프로세스를 종료한 회차는 `finalized=false`로 남을 수 있다.
불러오기 화면은 다음 단계이며, 상세 형식은 [세션 저장 계약](../../contracts/mapping/LIVE_SESSION_V1.md)을 따른다.

## 화면 회귀 검사

Node 내장 검사로 늦은 HTTP 응답·응답 본문 도중 탭 전환·이전 세션 거부와 카메라 권한 요청 시점을 검증한다.
권한 허용·거부·장치 중단은 합성 MediaStream 어댑터를 사용하며 실제 카메라 검증을 대체하지 않는다.

```powershell
node --test apps/console/tests/map-source.test.js apps/console/tests/capture.test.js
```

브라우저에서는 저장→실시간→저장 빠른 전환 후 저장 지도 점 수·단위·촬영 시점·내려받기 경로,
기록 재생과 최신 지도 복귀, 세션 없는 입력 전 화면 및 시작·중단 뒤 빈 지도를 확인한다.

완료/수신/초기화/갱신 실패를 구분해 표시한다. 실패 시 마지막 유효 지도를 유지한다.
온라인 지도의 단위는 실측 스케일이 없는 **임의 단위**다. 화면에 이를 표시하며 cm로 잘못 표기하지 않는다.
증분 온라인 지도는 새 면·유지한 면·건너뛴 기존 경계·깊이 확인 대기 시점을 표시한다.
계산 창 밖으로 나간 면도 같은 좌표 segment에서 유지하며 원본 시점 이미지를 계속 열 수 있다.
수신 프레임 추적과 3D 확정 시점은 다르다. 3D 면은 키프레임 자세 계산이 끝난 뒤 갱신된다.
상세 필드와 한계는 [온라인 공간 계약](../../contracts/mapping/ONLINE_SPATIAL_V1.md)을 따른다.

## 평면 객체 선택

`--objects <planar.py 출력 폴더>`를 추가하면 **객체·영상 표면** 모드에서 평면 앞면을 실제 영상으로 표시한다.
온라인 `--session`은 해당 revision에 포함된 객체와 텍스처를 자동으로 사용한다.
객체 목록이나 3D 면/이름표를 선택하면 크기·기하 일치 점수·지지점·여러 시점의 경계 근거를 확인할 수 있다.
`객체 확대`로 접근하고 `원본 시점 대조`로 촬영 위치에서 본다. 원본 미리보기에는 같은 3D 경계를 보라색,
지지점을 주황색으로 재투영한다. 슬라이더로 다른 시점에서도 정렬을 확인할 수 있다.
보라색은 세로·사각 면, 빨간색은 가로형 또는 대표 앞면과 다른 방향의 면이다. 빨간색이 실제 윗면이라는 의미는 아니다.
`전체 면`으로 검출된 면들을 한 화면에 맞춘다. 홀로그램에서도 면을 클릭해 같은 객체를 선택할 수 있다.
`객체 표시`와 `지지 특징점`을 따로 끌 수 있다.
원본 점군 모드는 객체를 숨긴다. 모드 전환은 현재 카메라 시점을 유지한다.

문 형태는 가로·세로 비율과 평면 경계에 따른 기하 후보다. 학습된 사물함 분류 확률이 아니며, 부피·내부 구조나
독립 치수 정확도를 보장하지 않는다. 지원 데이터가 없으면 빈 목록을 표시한다. 객체 묶음이 다른 지도에서
생성됐으면 `/api/run`은 503으로 거부한다. `/api/object-texture/`는 해당 묶음의 등록된 JPEG만 제공한다.
