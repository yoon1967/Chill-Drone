# 운영·결과 확인 화면

휴대폰 영상에서 계산한 실제 희소 점군과 카메라 경로를 확인하는 로컬 웹이다.
이번 복원 작업의 미리보기 구현이며 기존 EC2 상태 화면은 `infra/status/`에 유지한다.

## 설치와 실행

검증 환경: Python 3.12.14, Node.js 24.19.0, pnpm 11.25.0, Three.js 0.180.0, Chromium 기반 브라우저.
웹 서버는 Python 표준 라이브러리만 사용한다. Three.js는 설치 후 로컬에서 제공하므로
뷰어를 열 때 CDN·외부 API에 실제 자료를 보내지 않는다.

저장소 루트에서 [복원 실행](../../modules/mapping/localization/README.md)을 먼저 마친다.

```powershell
pnpm --dir apps/console install --frozen-lockfile
.\.venv\Scripts\python.exe apps/console/serve.py `
  --result output/phone_mapping/2f1_sfm_review --port 8790
```

브라우저에서 `http://127.0.0.1:8790/`을 연다. 서버를 종료하려면 실행 터미널에서 Ctrl+C를 누른다.
`--result`는 complete 또는 partial 상태의 복원 결과 폴더, `--port` 기본값은 8790이다.
단일 영상 실행 회차에서는 그 안의 reconstruction/을 지정한다. partial은 등록률 옆에 부분 복원으로 표시한다. 원본 프레임은 복원 당시 위치를 유지한다.
자료를 옮겼다면 새 위치에서 복원하거나 로컬 전용 `local_assets.json`의 `images_root`를 갱신한다.
원본 사진이 없어도 점군/경로는 열 수 있지만 촬영 키프레임 사진은 표시되지 않는다.
PNG·전체 처리 시간은 [파일 실행 안내](../../docs/phone_mapping/video_pipeline.md)를 따른다.
화면의 복원 소요 시간은 SfM·색상 구간이며 전체 영상→PNG 시간은 회차 루트 timing.json에서 확인한다.

## PC 카메라 입력

새 카메라 입력에는 프로젝트 Python 환경의 OpenCV·NumPy와 실행 중인 Docker Desktop이 필요하다.
`requirements-online.txt` 설치는 [온라인 실행 안내](../../modules/mapping/localization/ONLINE.md)를 따른다.
저장 결과 조회만 할 때와 달리 아래 옵션으로 카메라 입력을 켠다.

```powershell
docker build -t ssafy-orbslam3:local -f modules/mapping/localization/orbslam3/Dockerfile modules/mapping/localization/orbslam3
.\.venv\Scripts\python.exe -B apps/console/serve.py --enable-camera --port 8790
```

기존 저장 결과와 함께 보려면 `--result <완료 결과 폴더>`, 이전 카메라 기록도 열려면
`--session <세션 폴더>`를 추가한다. 이미 8790 서버가 실행 중이면 해당 서버의 세션을 종료한 뒤
같은 포트의 서버를 재시작한다. Docker 이미지가 없으면 위 build 명령으로 준비한다.

1. `http://127.0.0.1:8790/#live`의 영상 입력에서 **연결된 카메라**를 고른다.
2. **장치 새로고침**으로 목록을 읽고 카메라를 선택한다. 목록 조회는 권한을 요청하지 않는다.
   권한 전에는 이름이나 장치가 공개되지 않을 수 있으므로 기본 카메라로 시작할 수 있다.
   선택한 장치는 정확한 deviceId로 요청하며 다른 카메라로 자동 대체하지 않는다.
3. **카메라 연결 · 시작**을 누르고 카메라 권한을 허용한다. 마이크는 요청하지 않는다.
   원본 크기, 전송 크기, 카메라의 fps 설정값과 보정 사용 여부가 표시된다. fps 설정값은 실제 처리 성능과 다르다.
4. 무늬가 있는 정지된 공간을 계속 보면서 카메라 위치를 천천히 옮긴다. 영상 수신·정상 추적·3D 생성 상태를
   각각 확인한다. 고정 카메라나 제자리 회전만으로 유효 점군 생성이 보장되지는 않는다.
5. **수신 종료**로 카메라를 해제하고 지도 마무리를 기다린다. 권한 대기·연결 준비 중에도 취소할 수 있다.
   장치를 바꾸려면 종료 후 선택한다. 페이지를 떠날 때도 카메라 트랙과 해당 세션을 정리한다.

영상은 긴 변 최대 960px로 축소하고 JPEG와 media 시각·프레임 순번을 같은 PC의 서버로 전송한다.
인코딩·전송을 하나씩 진행하며 밀린 프레임을 계속 쌓지 않는다. 서버가 종료되거나 세션이 바뀌면
해당 카메라를 해제한다. 취소 뒤 도착한 이전 카메라·세션·프레임 응답은 새 세션에 적용하지 않는다.
권한 거부, 장치 없음·사용 중, 지원하지 않는 장치 설정은 안내를 보고 다시 시도할 수 있다.

**카메라 보정**의 JSON은 현재 렌즈·가로세로 비율·촬영 방향에 맞아야 한다. 다른 휴대폰 영상에서
계산한 값을 웹캠에 재사용하지 않는다. `width`, `height`, `fx`, `fy`, `cx`, `cy`는 유한한 숫자이며
`distortion`을 제공하면 `[k1, k2, p1, p2]` 숫자 4개다. 서버는 같은 비율의 전송 크기에 맞춰 내부 파라미터를
조절한다. 크기·초점거리·주점·왜곡 값이 잘못되면 SLAM 시작 전에 거부한다.
파일이 없으면 입력한 수평 화각을 사용하며 **화각 추정 · 미보정**을 표시한다. 실측 미터 단위나 치수 정확도를 보장하지 않는다.

정상 입력 후 지도가 초기화되기 전에 중단하면 **생성 전 종료**와 빈 점군을 표시할 수 있다.
`complete`는 입력 처리가 종료됐다는 뜻이며 `map_available`로 3D 생성 여부를 따로 확인한다.
추적 상실 뒤 새 지도 segment가 시작되면 이전 지도 점 수와 현재 지도 점 수가 다를 수 있다.
의도적인 렌즈 가림 후 같은 지도로 복귀하는 검증은 휴대폰 영상 시험에서 진행한다.

## 화면 사용

- 상단 **저장 지도**는 `--result`의 고정 실험 결과, **실시간 지도**는 현재 입력 세션 또는 `--session`의 기록을 표시한다.
  기본 탭은 저장 지도이며 `/#live`로 실시간 탭을 바로 열 수 있다. 브라우저 뒤로/앞으로, 탭에서 좌우 화살표·Home·End도 지원한다.
  해당 입력이 없으면 빈 상태를 표시한다. 저장 지도와 실시간 지도를 서로 대신 표시하지 않는다.
- 탭을 바꿀 때 이전 조회를 취소하고 늦은 응답을 무시한다. 같은 지도에 돌아오면 촬영 시점·3D 시점·표현 모드를 복원한다.
  실시간 입력은 탭 전환으로 종료하지 않으며 **수신 종료**로 끝낸다. 브라우저의 비활성/숨겨진 영상 전달 성능은 별도 검증 대상이다.
- 실시간 탭의 **영상 입력 / 특징점 추적 / 3D 지도**를 구분해서 읽는다. 영상 수신만으로 3D 초기화가 끝나는 것은 아니다.
  입력 전·권한 거부·장치 없음·연결 중단·지도 초기화 대기·마지막 유효 지도·완료 기록을 표시한다.
  페이지 열기와 탭 전환은 카메라 권한을 요청하지 않으며, 카메라를 선택하고 시작할 때만 요청한다.
- 드래그로 회전, 휠로 확대, 오른쪽 드래그로 이동한다. 입체·정면·위 시점을 선택할 수 있다.
- 최초 시점은 중심 구조에 맞춘다. 모든 점은 계속 렌더링되며 `전체 보기`는 외곽 점까지 포함해 맞춘다.
- **촬영 시점** 슬라이더는 선택한 지도의 키프레임 사진과 카메라 위치를 연결한다. `이 위치에서 보기`로 해당 카메라 방향을 확인한다.
- 실시간 탭의 별도 **지도 생성 시간** 슬라이더·재생은 실제 기록된 지도 revision을 교체한다. 첫 유효 지도 이전은 빈 점군이다.
  카드에는 최신 지도 상태와 현재 표시 중인 기록 버전·점 수를 함께 표시한다. **최신 지도**로 현재 수신을 다시 따라간다.
- 점 크기·색상·오차 필터, 촬영 경로·카메라 방향·격자를 조절한다. 필터는 표시만 바꾸고 원본 출력을 바꾸지 않는다.
- PLY, 카메라 자세 JSON, 경로 CSV를 내려받아 다른 도구에서 읽을 수 있다.

`reference_scaled`는 44cm 기준으로 맞춘 미터 단위, `arbitrary`는 미보정 임의 단위다.
미터 단위 격자의 한 칸은 0.5m다. 격자 평면은 표시용이며 실측 바닥·중력 방향이 아니다.
표면 메시·독립 치수 정확도·실시간 SLAM을 제공하는 화면으로 표시하지 않는다.

## 접근 범위

서버는 127.0.0.1에만 바인딩하고 정해진 정적 자원, 완료된 결과, 등록된 원본 프레임 이름만 제공한다.
저장소·실제 자료 디렉터리 열람, `.env`, 원본 DB, 로컬 절대 경로 JSON은 제공하지 않는다.
실제 촬영과 복원 결과는 Git·Sites·EC2에 업로드하지 않는다.

입출력은 [복원 결과 계약](../../contracts/mapping/PHONE_SFM_RESULT_V1.md)을 참고한다.
팀 작업 절차는 저장소 루트의 `docs/team/START_HERE.md`를 따른다.

## 공간 표현과 온라인 갱신

[온라인 처리 안내](../../modules/mapping/localization/ONLINE.md)에서 영상 수신과 영상 경계 기반 객체 복원을 준비한다.
웹 자체는 Python 표준 라이브러리와 설치된 Three.js를 계속 사용한다.

`--result <완료 결과> --objects <객체 폴더>`로 저장된 지도에 평면 객체를 붙이고,
`--session <온라인 실행 폴더>`로 수신 중이거나 기록된 지도를 연결한다. 두 입력을 함께 지정할 수 있다.
저장 결과는 `/api/saved/state`, `/api/saved/run`, 온라인 세션은 `/api/live/state`, `/api/live/run`에서
각각 조회한다. 실시간 세션을 새로 시작해도 saved 경로의 결과·단위·이미지·내려받기는 유지한다.
카메라 입력만 받을 때는 `--enable-camera`만으로도 시작할 수 있다.
상단 탭은 [소스 조회 계약](../../contracts/mapping/VIEWER_SOURCES_V1.md)의 saved/live 고정 경로를 사용한다.
이전 `/api/run` 호환 경로는 온라인 세션이 있으면 이를 따라간다.
웹은 2초마다 상태를 확인하고 새 revision만 가져온다. 지도와 객체는 같은 응답으로 읽는다.
갱신 중 사용자의 시점·표현 모드는 유지하며 좌표 segment가 바뀌면 시점을 다시 맞춘다.

- **객체·영상 표면**: 영상 경계와 여러 시점의 특징점으로 확인한 평면 객체에 실제 영상을 입힌다.
- **홀로그램**: 같은 객체의 면을 사진 질감 없이 반투명 발광 격자·스캔 효과·테두리로 표시한다. 원본 점군과 지지점도 확인할 수 있다. 모션 줄이기 설정에서는 스캔 애니메이션을 멈춘다.
- **원본 점군**: SfM 점과 오차 필터를 직접 확인한다.

홀로그램 탭의 **점 좌표 간격**은 지도 점들의 최근접 거리를 최대 256개 표본에서 계산해
소수 자릿수·슬라이더 범위·권장 간격을 정한다. 최근접 거리 중앙값의 자릿수보다 한 자리 더
세밀하게 조절한다(예: 약 0.0029인 지도는 0.0001 단위). 실제 조절 단위와 표본 거리도 표시한다.
숫자로 직접 입력하거나 **권장 간격 적용**을 누를 수 있다.
홀로그램 버튼을 누를 때마다 조정창을 열고 닫는다. 다른 탭으로 이동하면 즉시 닫고 홀로그램을
다시 누르면 연다. 창을 닫아도 선택한 간격은 유지하며 지도 재생·갱신이 창을 다시 열지 않는다.
간격 3에서는 각 축을 0, ±3, ±6… 중 가장 가까운 값으로 표시한다. 거리가 같은 경우에는 원점에서
먼 쪽을 선택한다. **원본 위치로** 또는 간격 0으로 복원한다. 같은 격자에는 한 점을 표시한다.
입력·저장·내려받기·촬영 경로는 유지하며 홀로그램 표시만 바뀐다. 원본 점군과 객체 모드는 원래
좌표를 사용한다. 재생·지도 갱신·오차 필터 후에도 선택한 간격을 다시 적용한다. 단위는 지도의
스케일을 따르며 단안 임의 단위를 미터로 해석하지 않는다.

그 아래 **신뢰 threshold**는 좌표를 모은 다음 서로 다른 관측 프레임의 합집합 크기를 검사한다.
기본값 3은 최소 3프레임 관측이며 숫자·슬라이더로 조절한다. 같은 프레임의 여러 점은 한 번만
센다. ORB 지도에서는 선택된 **키프레임** 기준이고 전체 처리 프레임 기준이 아니다.
격자 수·원본 점 수·실제 표시 수를 보여주고 만족하는 점이 없으면 빈 점군을 표시한다.
과거 결과에 프레임 연결이 없으면 개별 트랙 관측 수의 최대값만 하한으로 사용하고 격자 합산
불가를 표시한다. 관측 수는 기하 정확도나 사물 분류 확률이 아니다.
두 HUD는 함께 토글되며 원본 점군 탭에는 격자화·신뢰 필터를 적용하지 않는다.

점군의 인접 관계만으로 선·삼각형 메시를 생성하는 처리와 공간 셀 표시는 제거했다.
이전 온라인 결과도 점군과 영상 기반 객체만 읽는다. `--surface` 옵션은 지원하지 않는다.

`공간 안으로 이동`은 선택한 촬영 카메라 위치에서 탐색을 시작한다. WASD 전후좌우, Q/E 상하,
드래그로 시선을 바꾸고 Esc로 종료한다. 화면의 이동 버튼은 모바일에서도 사용할 수 있다.
이것은 시각 탐색 기능이며 벽 충돌·통과 가능·비행 경로의 안전성을 판정하지 않는다.

## 화면 회귀 검사

Node 내장 검사로 늦은 HTTP 응답·응답 본문 도중 탭 전환·이전 세션 거부와 카메라 권한 요청 시점을 검증한다.
권한 허용·거부·장치 중단은 합성 MediaStream 어댑터를 사용하며 실제 카메라 검증을 대체하지 않는다.

```powershell
node --test apps/console/tests/map-source.test.js apps/console/tests/capture.test.js
```

브라우저에서는 저장→실시간→저장 빠른 전환 후 저장 지도 점 수·단위·촬영 시점·내려받기 경로,
기록 재생과 최신 지도 복귀, 세션 없는 입력 전 화면 및 시작·중단 뒤 빈 지도를 확인한다.

완료/수신/초기화/갱신 실패를 구분해 표시한다. 실패 시 마지막 유효 지도를 유지한다.
온라인 지도의 단위는 실측 스케일이 없는 **임의 단위**다. 화면에 이를 표시하며 cm로 잘못 표기하지 않는다.
증분 온라인 지도는 새 면·유지한 면·건너뛴 기존 경계·깊이 확인 대기 시점을 표시한다.
계산 창 밖으로 나간 면도 같은 좌표 segment에서 유지하며 원본 시점 이미지를 계속 열 수 있다.
수신 프레임 추적과 3D 확정 시점은 다르다. 3D 면은 키프레임 자세 계산이 끝난 뒤 갱신된다.
상세 필드와 한계는 [온라인 공간 계약](../../contracts/mapping/ONLINE_SPATIAL_V1.md)을 따른다.

## 평면 객체 선택

`--objects <planar.py 출력 폴더>`를 추가하면 **객체·영상 표면** 모드에서 평면 앞면을 실제 영상으로 표시한다.
온라인 `--session`은 해당 revision에 포함된 객체와 텍스처를 자동으로 사용한다.
객체 목록이나 3D 면/이름표를 선택하면 크기·기하 일치 점수·지지점·여러 시점의 경계 근거를 확인할 수 있다.
`객체 확대`로 접근하고 `원본 시점 대조`로 촬영 위치에서 본다. 원본 미리보기에는 같은 3D 경계를 보라색,
지지점을 주황색으로 재투영한다. 슬라이더로 다른 시점에서도 정렬을 확인할 수 있다.
보라색은 세로·사각 면, 빨간색은 가로형 또는 대표 앞면과 다른 방향의 면이다. 빨간색이 실제 윗면이라는 의미는 아니다.
`전체 면`으로 검출된 면들을 한 화면에 맞춘다. 홀로그램에서도 면을 클릭해 같은 객체를 선택할 수 있다.
`객체 표시`와 `지지 특징점`을 따로 끌 수 있다.
원본 점군 모드는 객체를 숨긴다. 모드 전환은 현재 카메라 시점을 유지한다.

문 형태는 가로·세로 비율과 평면 경계에 따른 기하 후보다. 학습된 사물함 분류 확률이 아니며, 부피·내부 구조나
독립 치수 정확도를 보장하지 않는다. 지원 데이터가 없으면 빈 목록을 표시한다. 객체 묶음이 다른 지도에서
생성됐으면 `/api/run`은 503으로 거부한다. `/api/object-texture/`는 해당 묶음의 등록된 JPEG만 제공한다.
