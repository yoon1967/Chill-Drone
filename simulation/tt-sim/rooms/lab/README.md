# 실습실 실기체 자율비행 안내

Tello EDU + RoboMaster TT 확장 키트(전방 ToF)로 **지도 없이 출발해, 사람을 찾으며 카메라로 지도를 만든다**(탐색 비행).
실기체가 하는 비행은 이것 하나다(2026-11-03 결정). 경로 비행(앞 1–2 m)·장애물 1 m 앞 회피·지도 없이 둘러보기는 실기체에서 뺐고 Gazebo에만 남았다.
2026-11-04 기준이고, Claude 없이 이 문서만 보고 날릴 수 있게 적었다. 인터넷은 없어도 된다(모든 프로그램이 이 노트북 안에서 돈다).

## 1. 한눈에

창 세 개를 ① → ② → ③ 순서로 켜고, 끝날 때까지 모두 켜 둔다.

| 창 | 하는 일 |
| --- | --- |
| ① PowerShell | 중계: Windows ↔ 드론 신호를 넘겨줌 |
| ② WSL(Ubuntu-24.04) | 비행 프로그램 6개(드라이버·위치 추정·깊이 추정·YOLO·비행·웹 화면)를 한 번에 띄움 |
| ③ 브라우저 | http://localhost:8080 에서 점검을 보고 시작 |

① PowerShell:

```powershell
& "C:\Users\SSAFY\AppData\Local\Programs\Python\Python313\python.exe" -X utf8 \\wsl.localhost\Ubuntu-24.04\home\ssafy\ttrepo\modules\autonomy\tello_driver\tello_relay.py
```

② PowerShell을 하나 더 열어 WSL에 들어간 뒤(꼭 `Ubuntu-24.04`):

```powershell
wsl -d Ubuntu-24.04
```

```bash
cd ~/ttrepo/simulation/tt-sim && ros2 launch launch/real.launch.py
```

③ http://localhost:8080 에서 방향이 0° 근처인지, 점검이 모두 ✓이고 `YOLO 켜짐`인지 보고 → 운용자 확인 체크 → **[자율비행 시작]을 4초 안에 두 번**.

기본은 0.2 m/s로 120초 탐색한 뒤 출발점으로 돌아와 내린다. 바꿀 것은 [6절](#6-설정)에 있다.

**비행 중 손은 늘 키보드 위에 둔다.** 이상하면 `L`(착륙), 부딪힐 것 같으면 `Esc`(비상 정지, 떨어짐), 웹 화면이 멈추면 ② 창에서 Ctrl+C(착륙).
탐색 중에 드론이 볼 곳을 직접 정해 주려면 웹 지도를 한 번 클릭하고 **[여기로 보내기]**(`G`)를 누른다([가 볼 곳 찍어 주기](#가-볼-곳-찍어-주기)).

## 2. 비행 전 준비

### 미리 해 둘 것 (인터넷 될 때)

이 노트북에는 되어 있다. 다른 PC면 먼저 맞춘다.

- 코드: WSL **Ubuntu-24.04**의 `~/ttrepo`에 최신본([9절](#9-코드-받기))
- 파이썬 환경 `~/venvs/tt`(영상·깊이 추정·YOLO)와 YOLO 가중치. 깊이 모델(약 100 MB)도 내려받아 두어 인터넷 없이 된다
- Windows 방화벽: Python 3.13이 공용 네트워크에서 받기 허용. 드론 Wi-Fi는 **공용 네트워크**로 둔다(개인으로 바꾸면 막힐 수 있음)

### 체크리스트 (5분)

- [ ] 배터리 **완충(90% 이상)**. 58–72%로 이륙한 세 번은 20–40초 만에 기체가 스스로 내려앉았고, 83–90%로 이륙한 비행은 160–220초를 날았다
- [ ] 프로펠러 가드를 끼우고, 프로펠러에 금·휨이 없는지 본다
- [ ] 노트북 **충전기를 꽂고**, 삼성 설정 앱의 성능 모드를 **고성능**으로 둔다. 배터리로 돌면 GPU가 최대 클럭의 10–40%(11–14 W)로 묶여
      깊이 추정이 2배 넘게 느려진다(11/04 측정: 한 장 29 → 46–71 ms)
- [ ] 의자를 책상 안으로 밀고, 통로의 케이블·가방을 치우고, 조명을 켠다
- [ ] 출발 자리: 사방 1 m가 빈 **평평한** 바닥. 복도면 양쪽 벽에서 0.6 m 넘게 떨어진 가운데
- [ ] 바닥이 단색이면 출발 자리 둘레에 테이프로 X 무늬를 몇 개 붙인다(아래 카메라가 무늬를 봐야 제자리를 지킨다)
- [ ] 노트북 보관함·열린 선반·유리문 앞은 비행 범위에서 피하거나 사람이 옆에 선다
- [ ] 사람은 통로 밖에, 한 명은 웹 화면 [착륙] 앞에
- [ ] 폰 Tello 앱, 점검 화면(`check_server.py`)은 끈다(같은 포트를 쓴다)

### 드론 놓고 켜기

1. 드론을 출발 자리에, 앞이 **먼저 볼 쪽**(복도면 길이 방향)을 보게 놓는다. 켠 자리가 지도의 원점, 켠 방향이 +x가 된다.
2. **그 자리에서** 전원을 켜고, 켠 뒤에는 **손대지 않는다.** 돌리면 지도가 비스듬해진다.
3. 확장 키트 옆 스위치는 **아래**(AP, 직접 연결)에 둔다.
4. 노트북 Wi-Fi를 **`RMTT-9B10B2`**에 연결한다(처음이면 네트워크 종류는 **공용**). 키트가 없으면 이름이 `TELLO-59FA6D`다.
5. **켜고 2–3분 안에 띄운다.** 땅에 켜 둔 채로는 1분에 6–12°C씩 뜨거워져(영상을 켜면 더 빠름) 80°C면 이륙이 거절되고, 2–3분이면 스스로 꺼지기도 한다.

(선택) 비행 중에도 노트북 인터넷을 쓰려면 iPhone을 USB로 꽂고 개인용 핫스팟을 켠다(Apple Devices 앱 설치됨). 테더링 우선순위 값(25)이 Wi-Fi보다
작아서, 드론 Wi-Fi에 붙여도 인터넷은 테더링으로 나간다. 그래도 끊기면 관리자 PowerShell에서 `Get-NetAdapter`로 `이더넷`의 번호를 보고
`Set-NetIPInterface -InterfaceIndex <번호> -InterfaceMetric 10`, 끝나면 같은 명령에 `-AutomaticMetric Enabled`로 되돌린다.

## 3. 비행 절차

### ① 중계 켜기 (PowerShell)

[1절](#1-한눈에)의 ① 명령을 붙여 넣는다. 방화벽이 허용된 Python 3.13을 전체 경로로 부른다(`python`만 치면 다른 파이썬이 잡힐 수 있다).
5초마다 `명령 0, 응답 0, 상태 0, 영상 패킷 0` 같은 줄이 찍히면 정상이다. **이 창은 끄지 않는다.**

### ② 비행 프로그램 띄우기 (WSL)

PowerShell 창을 **하나 더** 열어 `wsl -d Ubuntu-24.04`로 들어간다(그냥 `wsl`은 ROS가 없는 다른 리눅스가 열린다). 그다음 ② 명령을 넣는다.
이런 줄이 나오면 준비된 것이다.

```text
SDK 모드 연결 (1번째 시도, 14.5 ms)
전방 ToF(확장 키트): 값 없음 (out_of_range, ...)   ← 앞 1.2 m 안에 물건이 없다는 뜻 (정상)
상태: READY
자율비행 웹 화면: http://localhost:8080
깊이 추정 준비 (cuda:0, 화각 54.7°, 깊이 배율 ×0.85)
YOLO yolo26n-seg.pt 준비 (cuda:0, 사람 윤곽 분할, ...)   ← launch 뒤 20초쯤. 이 줄 전에는 [자율비행 시작]이 회색
```

- 맨 위 `기록 폴더: …` 줄이 이번 비행의 기록 자리다.
- 전방 ToF가 `값 없음 (error_response)`이면 키트가 답하지 않는 것이다. 날리지 말고 키트를 다시 끼운 뒤 드론을 켠다.
- `연결 대기 중: command → timeout`만 계속 나오면 [7. 안 될 때](#7-안-될-때)를 본다.

### ③ 확인하고 시작 (브라우저)

1. **http://localhost:8080** 을 연다(Claude 앱 안 브라우저도 된다).
2. 오른쪽 **위치** 표의 방향이 **0° 근처**인지 본다. 아니면 켠 뒤 드론을 건드린 것이다 → ② Ctrl+C, 드론은 그대로 둔 채 ② 명령을 다시.
3. 점검 목록이 모두 **✓**이고 카메라 제목 옆이 `YOLO 켜짐`인지 본다. 마지막 줄 "주변 비움·가드·안전 담당"은 직접 체크한다.
   게이지 **기수 값 (Tello)** 이 멈춰 있는지도 본다(11/16). 숫자가 흐르고 `(흐름)`이 붙으면 Tello가 이륙을 거절해 왔다 — 버튼 아래에 이유가
   뜨고, 시작을 눌러도 비행 노드가 받지 않는다. 기체를 살짝 들었다 평평한 곳에 다시 내려놓고, 방향이 0°에서 벗어났으면 ②를 다시 띄운다.
4. **[자율비행 시작]을 4초 안에 두 번** 누른다. 첫 번째에 버튼이 "주변 확인 후 한 번 더 누르면 이륙"으로 바뀌고, 두 번째에 이륙한다.

화면에서 볼 것:

- **맨 위 띠 — 지금 하는 일과 이유**(11/16). 탐색 중에는 `자율 탐색 중 · 남은 탐색 시간 1:20`, 시간이 다 되면
  `출발점으로 돌아가는 중 · 이유: 탐색 시간(120초)이 다 돼`, 내리면 `내린 이유: …`(중단이면 `중단 · 이유: …`)가 뜬다.
  드론이 갑자기 돌아가거나 내리면 먼저 이 띠를 본다.
- **YOLO 배지** `YOLO 켜짐 · 초당 5번 · 지금 사람 N명`. YOLO가 돌면 영상이 **YOLO 탐지** 탭(사람 상자)으로 바뀐다.
- **지도**: 보라 칸은 막힌 곳(옅은 보라는 의심, 경로는 피함), 연한 바탕은 본 곳, 주황 원은 찾은 사람이다. 칠한 원은 길을 막는 사람, 점선 원은
  다시 봤는데 없어 길에서 뺀 사람이다.

### 가 볼 곳 찍어 주기

탐색하는 동안 드론이 **다음에 볼 자리**를 웹 지도에서 직접 정해 줄 수 있다(11/11). 가는 길·장애물 피하기·문 지나기는 평소처럼 드론이 스스로 한다.
하지 않아도 되는 조작이다 — 아무것도 찍지 않으면 전과 똑같이 스스로 탐색한다.

1. 웹 **지도를 한 번 클릭**한다(끌면 지도 이동, 두 번 클릭은 처음대로). 그 자리에 청록 점선 십자 `보낼 자리`가 찍힌다. 아직 가지 않는다.
2. 지도 아래 **[여기로 보내기]**(또는 **`G`**)를 누른다. 기록에 `비행 노드: 찍은 자리 (…)를 받았습니다`가 뜨고, 드론은 가던 길을 멈추고 그리로 간다
   (둘러보는 중·물러나는 중·문을 지나는 중이면 그 동작을 마친 뒤). 지도에 청록 점 `가는 중`.
   비행 노드의 답(받음·거절·그만둠)은 **버튼 바로 옆에 20초** 뜬다 — 거절·그만둠은 주황색(11/16).
3. 도착하면 둘러본 뒤(`둘러보는 중`) 자율 탐색을 잇는다. 탐색 시간(`search_time`)이 다 되면 평소처럼 돌아온다.
4. **탐색 시간이 다 돼 돌아가는 중에도 찍으면 간다**(11/16). 돌아가기를 멈추고 그리로 가 둘러본 뒤 다시 출발점으로 돌아간다.
   더 보고 싶으면 또 찍으면 된다. 배터리 10%·온도 자동 착륙과 `L`은 그대로다.

- **본 곳(연한 바탕) 안을 찍으면 그 자리로, 그 밖을 찍으면 그쪽으로 간다.** 막힌 칸이나 아직 못 본 곳을 찍으면, 드론이 갈 수 있는 빈 자리 가운데
  찍은 곳에 가장 가까운 자리로 가서 찍은 쪽부터 본다(지도에 찍은 곳은 빈 원, 갈 자리는 칠한 점; 기록 `… 갈 수 있는 자리 (…)로 가서 찍은 쪽을 봅니다`).
  본 곳으로 보여도 아직 길이 이어지지 않은 자리면 똑같이 가장 가까운 자리로 옮긴다(기록 `… 아직 길이 이어지지 않아 …`). 멀리 찍으면
  '그쪽으로 가 보라'는 뜻이 된다. 이미 그쪽으로 가장 가까이 와 있으면(0.5 m도 더 못 다가가고, 찍은 곳 1.5 m 안에 갈 자리도 없음) 받지 않고 하던 탐색을 잇는다.
- **찾은 사람·장애물 둘레가 길을 막고 있으면 여유를 줄여서 간다**(11/12). 자율 탐색이 볼 자리가 없을 때 하는 순서 그대로다: 찾은 장애물 둘레
  0.3 → 0.2 m, 카메라로만 본 장애물 빼기, 찾은 사람 둘레 0.35 → 0.15 m, 몇 번만 잡힌 사람 빼기, (0.6 m 안이나 사방에 사람이 없으면) 몸 둘레 0.1 m만.
  찍은 곳 1.5 m 안까지 길이 이어지는 첫 단계에서 멈추고, 기록에 `… 찾은 장애물·사람 둘레가 막고 있어, … 갑니다`가 뜬다. 어느 단계로도 안 되면
  아무것도 줄이지 않고 받지 않는다. 줄인 여유는 그 자리에서 2 m 벗어나면 되돌린다. 줄인 뒤에는 **찾은 사람 중심에서 0.4–0.5 m 옆으로 0.12 m/s 경로가
  날 수 있다** — 사람이 서 있는 쪽을 찍었으면 `L`을 누를 준비를 한다(카메라가 본 몸·ToF·비상 정지는 그대로 피한다).
  **사람이 실제로 길목에 서 있으면 다가가다 그만둔다**: 가까이 가면 사람이 다시 장애물로 잡히고, 사람 1.2 m 안의 틈은 지나지 않는 규칙이 그대로라
  `… 가는 길이 없습니다`로 끝난다(Gazebo 3판: 폭 1.6·1.8 m 입구 가운데 사람, 1.2 m 간격 두 사람 — 닿음 0번, 사람과 0.47 m 넘게 남김).
  이 기능이 길을 여는 것은 사람이 이미 비켰거나 잘못 놓인 장애물이 막고 있을 때다.
- 못 가게 되면 기록에 이유가 뜨고 하던 탐색을 잇는다: `… 가는 길이 없습니다`, `… 가다 그만둡니다: 재계획 7번`(포기 기준은 평소 볼 자리와 같다).
- 가는 중에 다른 곳을 찍어 보내면 그리로 바꾼다. **[가기 취소]** 는 찍은 자리를 버리고 자율 탐색으로 돌아간다.
- **돌아가는 중**에도 받는다 — 더 볼 곳이 없어서든 탐색 시간이 다 돼서든(돌아가기를 멈추고 그리로 간다). 시간이 다 된 뒤에 받은 자리는
  둘러본 뒤 자율 탐색으로 가지 않고 다시 돌아간다(`… 탐색 시간(120초)은 다 됐지만 찍으셨으므로 … 다녀옵니다`). 이륙 중, 출발점 위 한 바퀴·
  착륙 중에는 받지 않는다(버튼 옆과 기록에 `… 받지 않습니다: …`).
- 찍은 자리는 **어디를 볼지**만 정한다. 드론이 못 보는 것(유리·열린 선반)은 그대로 못 보므로 `L`(착륙)·`Esc`(비상 정지)를 누를 준비는 그대로 한다.

## 4. 탐색 비행이 하는 일

### 흐름

1. 이륙(약 9초)해 1.0 m로 오른다.
2. 제자리에서 둘러보며 카메라로 지도를 채운다(웹 단계 `LOOK`). 둘러본 자리(이륙 직후 출발점 포함)는 기억해 그 1 m 안은 다시 볼 자리로
   고르지 않는다(11/09).
3. 아직 못 본 경계(복도 끝, 문 너머)가 보이는 자리를 골라 간다. **카메라로 본 빈 곳으로만** 다닌다.
   - 이미 앞을 다 본 곳은 다시 가지 않는다. 가구·벽에 붙은 모르는 칸(선반 칸 안, 가구 뒤)은 못 본 곳으로 치지 않는다.
   - 볼 자리는 둘레 0.45 m가 빈 곳(좁은 복도는 0.2 m)이고, 그 가운데 **둘레 1 m가 빈 자리를 먼저** 고른다(11/14 — 전에는 가는 길에서
     가장 가까운 후보라 벽 옆이 됐다: 둘러본 25곳 중 84%가 벽 0.7 m 안). 통로는 가운데로 지나고, 벽 옆에서 출발해도 벽을 따라가는
     직선으로 줄이지 않고 벽에서 떨어져 돌아간다.
   - 고르는 기준은 **그 자리에서 3 m 안에 새로 보일 넓이 ÷ (1 + 거리/6 m)** 다(11/04). 광선은 막힌 칸에서 멈춘다. 새로 보일 것이
     0.3 m²도 안 되는 곳은 가지 않는다. ② 창 `다음 볼 자리 (…): 새로 보일 곳 약 … m²(경계 …칸), … m 거리`.
   - **가는 길이 계속 막히면 포기한다**(11/04): 재계획이 6번을 넘거나(1초에 한 번까지만 셈), 앞·옆으로 움직이는 동안 12초가 지나도 남은 길이 0.3 m도 줄지 않으면
     그 자리 둘레 1.5 m를 빼고 다른 곳을 고른다(제자리 회전은 세지 않음). 좁은 길(줄인 여유 0.2 m)로만 길이 나온 자리는 3번·8초다.
     ② 창 `볼 자리 (…)를 포기합니다: …`. **문 너머 자리는 예외**(11/05): 평소 한도를 쓰고, 포기해도 둘레 0.6 m만 빼며
     (`… (문 너머라 문은 막지 않고, 더 볼 곳이 없으면 다시 봅니다)`), 더 볼 곳이 없으면 한 번 더 고른다(`금지를 풀고 다시 골랐습니다`).
   - **문은 멈췄다 곧게 지난다**(11/05): 경로가 폭 약 1.2 m 안의 틈을 지나면 ② 창 `경로가 폭 … m 틈(문, …)을 지납니다` → 문 가운데 선 위
     0.8 m 앞에 멈춰 문을 정면으로 보고 다시 잰 뒤, 정면 ToF가 문 너머까지 비었으면 `… 0.15 m/s로 곧게 지납니다` → `문을 지났습니다`.
     지나는 중 빠져나갈 자리 앞에 무엇이 보이면 `문 지나기를 그만둡니다`로 멈추고 물러난다. 웹 단계 `DOOR`.
     볼 자리가 방금 지나온 틈 안(옆 0.6 m)이었으면 되돌아가지 않고 나온 자리에서 바로 둘러본다(11/11).
     폭 1.05 m 넘는 틈인데 앞뒤 1 m까지 양옆 벽이 같은 간격으로 이어지면 복도로 보고 멈추지 않는다(11/11) —
     ② 창 `… 복도라 문 지나기를 쓰지 않고 보통 경로로 갑니다`.
   - **남은 시간 안에 갈 수 있는 곳만** 고른다(11/04): 남은 탐색 시간 × 속도 × 0.7(최소 1.5 m) 안. 그 안에 볼 곳이 없으면 일찍 돌아온다 —
     ② 창 `남은 …초 안에 갈 수 있는 … m 안에 더 볼 곳이 없어 출발점으로 돌아갑니다`.
   - **닫힌 공간은 마치고 다른 곳으로 간다**(11/04 저녁): 못 본 곳으로 이어지는 틈이 30×30 cm보다 작거나(작은 구멍) 막혀 있으면(닫힌 창 포함)
     그 너머는 볼 곳으로 치지 않는다. 30 cm 넘는 틈(문·좁은 통로)은 그 입구를 볼 곳으로 넣는다(전에는 60 cm보다 좁은 통로를 놓쳤다).
     지금 공간(5 m 안)에 그런 통로가 없으면 ② 창 `지금 공간(…)은 30×30 cm 넘는 통로가 없는 닫힌 공간입니다(창·가구 너머 …곳, 작은 구멍 …곳,
     이 안에서 찾은 사람 …명). 이 공간 탐색을 마치고 (…) 쪽 통로로 갑니다`.
   - **닫힌 창은 막힌 것으로 본다**(11/04 저녁): 창턱(0.5–1.2 m)과 같은 벽면(0.2 m 안)에 창 위 벽(1.9–2.3 m, 0.5 m 넘게 이어짐)이 있고 그 사이가
     비어 보이면 창으로 보고, 그 위로 넘는 길을 지도에서 막는다. 탁자·의자처럼 위가 빈 가구 위로는 그대로 넘는다(10:17 비행은 떠 있던 시간의
     77%를 1.2 m 위에서 날았다). 드론이 이미 지나온 자리는 창으로 치지 않는다. **창 위 벽이 지도에 잡혀야** 창으로 본다(아래 '못 보는 것').
   - **운용자가 웹 지도에서 찍은 자리가 있으면 그 자리가 다음 볼 자리다**(11/11, [가 볼 곳 찍어 주기](#가-볼-곳-찍어-주기)). 위 점수·남은 시간
     거리는 따지지 않고, 가는 길·포기 기준·문 지나기는 같다. 못 가도 '못 간 자리'로 세지 않는다(그 수가 20이면 탐색을 끝낸다).
     ② 창 `찍은 자리 (…)로 갑니다 (… m 거리). 도착하면 둘러본 뒤 자율 탐색을 잇습니다`.
4. 사람을 찾으면 자리를 적는다(웹 지도 주황 원, `people.json`).
5. `search_time`(120초)이 지나면 출발점으로 돌아와 내린다. `return_home:=false`로 띄우면 돌아가지 않고 그 자리에 내린다(11/11).
   남은 시간과 돌아가는 이유·내린 이유는 웹 맨 위 띠에 뜬다(11/16). 돌아가는 중에 운용자가 자리를 찍으면 그리로 다녀온 뒤 다시 돌아간다.

### 지도

- 지도 파일은 쓰지 않는다. 켤 때마다 **출발점이 가운데인 빈 지도**(한 변 20 m)로 시작한다. 켠 자리가 원점, 켠 방향(드론 앞)이 +x, 그 왼쪽이 +y다.
- 테두리 밖으로는 날지 않는다. 범위를 좁히려면 `area:=`를 줄여 울타리로 쓴다.
- 벽·가구는 카메라 영상의 깊이 추정(Depth Anything V2, 노트북 GPU)과 전방 ToF로 찾아 3D 지도(`camera_map.npz`)에 쌓는다. 카메라가 앞쪽 위도
  보므로 가구 위 빈 공간도 담긴다.
- **깊이 배율은 정면 ToF로 맞춘다**(11/04): ToF가 1.2 m 안에서 면을 잴 때마다 같은 방향 깊이와 비교해 0.5초에 하나씩 모으고, 최근 300초
  중앙값을 깊이에 곱한다. 전에는 화면 아래 바닥으로 맞췄는데 실기체에서는 바닥이 잘 안 보여 1.30에 붙었고, 깊이가 30% 멀게
  들어갔다. ② 창 `깊이 배율 1.00 → 0.93 (정면 ToF와 비교한 최근 …개 중앙값)`. **천천히 움직인다**(11/11): 표본이 적을수록 1.0 쪽으로
  당기고 0.8–1.25 안에서만 쓴다 — 전(60초 중앙값, 0.7–1.4)에는 한 비행 안에서 0.70 ↔ 1.29로 튀어 같은 벽이 다른 자리에 또 찍혔다
  (실기체 가방 6개로 확인: 먼 거리 오차 평균 24.5% → 20.9%).
- **판단 속도**(11/04): 깊이 추정·YOLO는 초당 10번(전에는 5번), 계획용 지도는 0.5초마다(전에는 1초) 다시 만든다.
- 이 폴더의 실습실 지도(`room_v2.json`, `make_maps.sh` 등)는 Gazebo 실습실 월드를 만드는 데만 쓴다.

### 사람을 찾으면

- YOLO(`yolo26n-seg`, 사람 윤곽)가 늘 같이 돈다. 끌 수 없고, 준비되기 전(launch 뒤 20초쯤)에는 시작하지 않는다.
- 사람을 잡으면 ② 창에 `사람 탐지 1명 (… 깊이 약 1.8 m)`, `사람 발견 #1: (x, y)`가 찍힌다. 1.3 m 안의 사람은 장애물로 넣어 돌아간다.
- **지나간 사람**: 찾은 자리를 다시 똑바로 봤는데 아무도 없고 깊이로도 비어 있으면, 그 사람은 길을 막지 않는다(웹 지도 점선 원).
- **사람이 길을 막으면 기다리지 않는다.**
  1. 사람 둘레 여유를 0.35 m에서 0.15 m로 줄여 사이로 지나간다.
  2. 막은 사람이 모두 낮으면(머리 약 1.0 m 이하, 앉은 사람 등) 위로 넘는다. 선 어른은 넘지 못한다.
  3. 그래도 길이 없을 때, 사람이 0.6 m 안이거나 1 m 안의 세 명 넘게가 사방을 둘러쌌으면 **그 자리에 착륙**한다. 아니면 그 사람들의 둘레 여유를
     몸 둘레 0.1 m만 남기고 **탐색을 이어 간다**(카메라가 본 몸·ToF·비상 정지는 그대로 피한다). 찾은 사람 1 m 안에서는 0.12 m/s로 간다(11/10,
     ② 창 `찾은 사람이 … m 옆에 있어 0.12 m/s로 갑니다`).

| 막힌 주머니 (둘레 0.25 m 안이 막혀 돌 수 없고, 정면 왼쪽·오른쪽 1 m 안이 모두 막힘) | 기수를 돌리지 않고 들어온 자취로 곧게 후진(0.18 m/s). 돌 자리가 생기면 끝내고(0.2–1.5 m) 돌아서 정면으로 간다. 2 m 안에 사람이 있었으면 후진하지 않고 천천히 돈다. 되짚을 자취가 기수 쪽(뒤에서 100° 넘게)이면 후진하지 않는다(11/11) | `돌 자리가 없고 … 후진합니다` → `… 후진했습니다 (돌 자리가 생겨 …)`, `되짚을 자취가 기체 앞쪽…` |
| 낮은 가구 (꼭대기 약 1.3 m 이하) | 카메라가 빈 것으로 본 위 공간으로 넘고 1.0 m로 내려옴 — 넘을 곳 1 m쯤 앞에서 오르고 넘자마자 내려온다(11/11). 정면 ToF가 잡은 것(비행 높이에 있는 것)은 꼭대기를 모르므로 넘지 않고 돌아간다(11/11). 밑이 0.35 m보다 가까우면 바로 오름. 높이는 하방 ToF로 재되, 하방 ToF는 바로 밑 물건까지 거리다: 카메라 지도가 기체 밑에 가구가 있다고 알면 높이 = ToF + 그 꼭대기, 지도에 없는데 ToF만 줄고 Tello 높이는 그대로면(평소 차이보다 0.4 m 넘게) 가구로 보고 Tello 높이로 이어 간다 — 조금씩 줄어도(11/09 17:07) | `비행 높이 1.00 m (가구 위로 넘을 때 1.85 m까지, 천장 2.5 m)`, `바로 밑 … m에 무엇이 있습니다` |
| 앞이 확실히 빔 (카메라 정면 3 m 넘게 비고, ToF에 없고, 경로가 곧음) | 0.4 m/s까지 빠르게 | `앞 … m가 비어 0.40 m/s로 갑니다` |

옆으로는 거의 움직이지 않는다(0.05 m/s까지). 옆을 보는 센서가 없으니 기수를 돌려 앞으로 간다.

### 못 보는 것

- 전방 ToF는 빛줄기 하나(원뿔 약 25°, 1.2 m까지)다. 카메라 깊이는 단안 추정이라 유리·거울·무늬 없는 흰 벽에서 틀릴 수 있다.
  유리는 ToF가 0.2 m쯤에서야 잡기도 하니, 유리문·유리벽이 많은 곳은 피하거나 사람이 옆에 선다.
- **창문 유리는 ToF도 통과할 수 있다**(11/04: 창턱 0.5 m 앞에서도 ToF 값 없음). 그러면 깊이가 창밖까지 빈 곳으로 칠한다. 창턱과 창 위 벽이
  지도에 잡히면 닫힌 창으로 보고 그 너머는 가지 않지만(4절), 창 위 벽이 지도에 안 잡히면(창이 천장까지 닿음, 깊이가 위 벽을 창밖으로 읽음) 창턱 위
  1.5–1.85 m로 **창을 지나가려 할 수 있다** — Gazebo 창 월드에서 한 번 그랬다. 창가에서 날릴 때는 사람이 창 옆에 서서 `L`을 누를 준비를 하고,
  창이 많은 곳은 `area:=`를 줄여 울타리를 치거나 창을 등지고 출발한다.
- 옆과 위를 보는 센서는 없다. 얇은 선반 판이 기체 옆에 닿을 수 있다(11/03 14:32). 천장이 낮거나 등·배관이 드리운 곳은 `ceiling:=`을 낮춘다.
  라운지·실습실은 책상 위 1.9–2.3 m에 덕트·등, 매달린 표지판이 있어 11/09 17:07에 Tello 높이 1.9–2.0 m(기본 상한 2.0 m 아래)에서
  천장에 눌렸다. 그곳에서는 `ceiling:=2.1`(상한 1.6 m, 가구 위로 넘을 때 1.45 m까지)로 띄운다.

- [ ] **rc가 ToF 조회에 밀리지 않는지(11/04 밤)**: 드라이버 기록 `commands.jsonl`에서 rc 사이 간격이 0.15초를 넘는 때가 없는지(전에는 최대
      523–571 ms). ② 창에 `위치가 …초째 안 옵니다`·`전방 ToF가 …초째 안 옵니다`가 평소 비행에서는 안 찍히는지
- [ ] 기둥 앞에서 `기둥(폭 …)`으로 옆으로 지나가고, 벽 앞에서 `벽(폭 …)`으로 방향을 바꾸는지
- [ ] 앞이 빈 곧은 복도에서 `0.40 m/s로 갑니다`가 찍히고, 장애물·사람 앞에서는 0.2 m/s로 돌아오는지. 불안하면 `fast:=0`
- [ ] 가구 위로 넘기: 먼저 `flight_height:=1.6`으로 떠서 1.5 m 넘어서도 높이(하방 ToF)가 읽히는지 본다(안 읽히면 `height_limit:=1.4`).
      그다음 0.7 m쯤 상자를 길에 가로놓고, 넘은 뒤 1.0 m로 내려오는지

**기체**

- [ ] 보고서의 "실제로 낸 속도"가 설정(`v_full` 1.03, `yaw_full_deg` 50)과 20% 안인지. 10/30에는 회전이 rc 67에 59°/s로 더 빨랐다
- [ ] 이륙 거절이 되풀이되면 [7절](#7-안-될-때)의 이륙 거절 줄대로 본다
- [ ] **이륙 전 기수 값(11/16)**: 켠 뒤 웹 게이지 '기수 값 (Tello)'이 멈춰 있는지, 흐를 때 버튼 아래에 이유가 뜨고 시작이 안 받아지는지,
      기체를 들었다 다시 놓으면 멈추는지. **거절됐을 때 기체를 건드리지 말고 바로 폰 앱으로 띄워 보기** — 앱으로는 뜨면 SDK 쪽 기준이 더
      엄한 것이고, 앱도 안 뜨면 기체 상태다(아직 못 가렸다). 끝 로그의 `시작을 안 받음 …번·이륙 거절 …번`도 본다

## 6. 설정

② 명령 뒤에 `이름:=값`으로 붙인다. 예를 들어 `ros2 launch launch/real.launch.py search_time:=60 speed:=0.15`.

cd ~/S15P31B205 && git pull
